# 作业一｜五页 PPT 版式讨论稿

> 只确定信息层级和空间排布，不制作正式内容 PPT。采用用户提供模板的 16:9 白底、天蓝与草绿配色；去除公司名、Logo、网址和标语。以已修改的五页文本稿和六类职能画像为内容来源。P1 总论、P2 时间轴、P3～P5 双职能画像，共五页。

## P1｜组织变化与目的：先给 CEO 一个完整判断

**建议标题**：组织从分散职能走向可复制的全球运营能力。

```text
┌─────────────────────────────────────────────────────────────┐
│ 标题：组织变化与目的                                            │
│                                                             │
│ 当前状态          0～1年组织补位           2～3年基地嵌入      3年后平台治理 │
│ 计划/供应链空缺 → 计划＋仓储物流＋数字化 → 骨干派驻/双线协作 → 职能融合    │
│ 信息化按系统分工   IE联合现场（归属待定）    基地承担执行       共性规则入平台 │
│                                                             │
│ 目的：现场事实驱动计划和实物流｜3～6个月寻找收益｜跨基地复制与治理       │
│ P5角标：融合团队总人数中，至少2人能协同掌握“全系统”运作             │
└─────────────────────────────────────────────────────────────┘
```

**取舍**：这一页只讲组织为什么变、朝哪里变。具体人数与阶段收益留给 P2；不在总论页塞入全部岗位画像。“两人”是团队能力覆盖要求，保障各基地业务与系统运行顺畅，不表示每基地各配两人，也不等于两人承担所有现场工作。

## P2｜五阶段时间轴：人员配置、目标、预期收益在一页

**建议标题**：组织能力逐步形成，收益从先导项目走向跨基地复制。

```text
┌─────────────────────────────────────────────────────────────┐
│ 0～6月       6～12月       1～2年       2～3年       3年后       │
│   ●──────────●──────────●──────────●──────────●                │
│ 组织/人员     组织/人员      组织/人员     组织/人员     组织/人员   │
│ 阶段目标      阶段目标       阶段目标      阶段目标      阶段目标    │
│ 收益方向      收益验证       复制收益      基地收益      平台收益    │
│                                                             │
│ 页脚：人数均为设想；收益由业务基线、财务口径与实施投入共同验证          │
└─────────────────────────────────────────────────────────────┘
```

**各列的展示重点**：

| 时间 | 人员配置／组织状态 | 阶段目标 | 预期收益或验证点 |
|---|---|---|---|
| 0～6个月 | 计划、仓储物流和数字化归位；开发 1 人、IE 协作 1 人为设想 | 建基线，宁德先导机制运行 | 3～6个月观察时间、质量、作业损失改善 |
| 6～12个月 | 计划 4～6、数字化业务 2～3、开发集成 1～2、体系 1 人为设想；仓储和 IE 按业务量确认 | 业务、系统与财务能对上口径 | 正式核算增量贡献、成本节约和库存现金释放 |
| 1～2年 | 承接上一阶段配置；基地按业务量增配 | 方法沉淀成可复制标准 | 各基地单独建基线，验证复制后的交付、成本、库存 |
| 2～3年 | 集团培养的计划与仓储骨干派驻基地；实线基地、虚线集团 | 海外基地能独立执行并反馈 | 交付稳定、跨基地指标一致、改善结果可核算 |
| 3年后 | 骨干轮换；体系与 IE 融入数字化；约 5 人融合团队为能力验证设想 | 平台承接共性规则和部分协调工作 | 全球运营收益、外部依赖和平台维护投入共同评估 |

**排版限制**：每列只放短语，不放段落；数字标注“设想”。具体指标和判断依据放讲稿备注或配套 MD。

## P3｜计划人员 × 仓储／实物流人员

**建议标题**：计划与实物流共同对交付结果负责。

```text
┌─────────────────────────────────────────────────────────────┐
│ 左上：计划画像＝数字敏感、懂业务约束和软件边界                     │
│ 右上：实物流画像＝能把图文变成场景和动作、能规划仓储物流              │
│                                                             │
│              P1       P2       P3       P4       P5            │
│ 计划能力      现场核对 → 可执行计划 → 规则软件化 → 基地派驻 → 轮换晋升  │
│ 实物流能力    风险识别 → 过程优化   → 新基地规划 → 基地派驻 → 轮换晋升  │
│                                                             │
│ 底部共同接口：计划指令 ↔ 物料动作 ↔ 现场反馈                       │
│ 验证：交付预测／库存、账实与搬运损伤、派驻后业务连续性               │
└─────────────────────────────────────────────────────────────┘
```

**强调**：基地本地接任人员由这两类骨干培养，不另起第三种画像。P4 的派驻与 P5 的轮换在两条能力线上同时体现。

## P4｜数字化业务人员 × 开发／集成人员

**建议标题**：业务理解与工程能力双向靠近，最终形成融合团队。

```text
┌─────────────────────────────────────────────────────────────┐
│ 两个起点：业务人员走入现场               工程人员理解物理场景        │
│                                                             │
│              P1       P2       P3       P4       P5            │
│ 业务能力      数据断点 → 功能价值   → 标准/模板 → 物理投影 → 轮岗融合 │
│ 工程能力      接口保障 → 测试发布   → 复制部署 → 软硬接入 → 轮岗融合 │
│                                                         ↘   │
│                                    全系统＋AI工具的自主交付能力？     │
│ 底部验证：业务使用、数据质量、系统稳定、供应商依赖                 │
└─────────────────────────────────────────────────────────────┘
```

**强调**：P5 的“自主搭建”是验证问题，不是结论。AI 降低重复编码量，接口、测试、部署、稳定性和安全仍需要工程能力。

## P5｜供应链体系人员 × IE 人员

**建议标题**：把客户体系要求与现场精益方法写进数字化运营。

```text
┌─────────────────────────────────────────────────────────────┐
│ 两个专业视角：体系定义运营边界           IE 测量并优化现场动作     │
│                                                             │
│              P1       P2       P3       P4       P5            │
│ 体系能力      盘点要求 → 控制点   → 集团标准 → 基地适配 → 平台内嵌   │
│ IE能力       现场测量 → 过程改善 → 方法复制 → 数字接口 → 模型共建   │
│                                      IE前期联合参与，归属待讨论    │
│                                                         ↘   │
│                  与数字化业务团队融合，形成“体系＋精益”的系统规则   │
│ 底部验证：控制点覆盖、动作/等待损失、跨基地一致性与实际收益          │
└─────────────────────────────────────────────────────────────┘
```

**强调**：P1～P4 不把 IE 的组织归属提前写死；P5 并入数字化团队要以业务和平台能力成熟为条件。
