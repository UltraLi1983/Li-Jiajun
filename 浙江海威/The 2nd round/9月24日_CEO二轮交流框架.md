## 一、交流目标

本次交流希望完成六件事：

## 二、核心主张

海威正在进入业务规模扩大、上市准备和海外多基地发展的新阶段。这个阶段需要建立贯通以下环节的供应链与数字化运营能力：

**客户需求 → 交付预测 → 产能评估 → 生产计划 → 现场执行 → 物料流动 → 异常处理 → 计划调整 → 客户交付**

我的价值不只是理解信息系统，也不只是开发软件，而是：

> 从经营目标出发，识别供应链和现场运营问题，建立相应的管理机制，并通过数据、软件和现场方案把机制真正落地。

工具是手段，最终目标是提升：

- 交付的可预测性；
- 客户服务的可靠性；
- 产能和运营效率；
- 供应链整体成本；
- 经营过程透明度；
- 国内运营能力向海外基地复制的速度。

### 阶段二：系统功能与业务实质对齐

建议时间：30—45 分钟。

以《海威集团信息系统方案说明 260617》为起点，但不只是审核功能清单。每项功能围绕以下问题展开：

1. 这个功能解决什么业务问题？
2. 谁在什么场景使用？
3. 数据产生后触发什么业务动作？
4. 它最终影响交付、质量、效率、成本还是风险？
5. 当前是已经落地、部分落地，还是计划建设？

#### 4.3 从系统模块转为业务能力

建议将 WMS、MES、QMS、TPM、IoT 重新归入以下业务能力：

1. **实物与物料流管理**
   - 收货、库存、盘点、FIFO、发料、退料、WIP、成品和交付。

2. **供需与生产计划**
   - 客户需求、交付预测、产能评估、调度派工、进度反馈和重排。

3. **生产过程与工艺控制**
   - 作业执行、报工、工艺参数、防错、追溯、设备和工装条件。

4. **质量管理与过程闭环**
   - 检验、判定、隔离、不合格品处置、放行、SPC 和持续改善。

5. **数据采集与经营决策**
   - 采集对象、频率、数据用途、责任人、触发动作和管理输出。

核心讨论问题：

> 我们现在规划的是一组系统功能，还是一套从客户需求到交付结果的运营能力？

#### 4.4 QMS 的讨论方式

不建议把问题简单表述为“QMS 到底是不是运营相关系统”，因为容易陷入模块归属和名词争论。

更有效的问题是：

> QMS 中哪些功能只是记录和展示，哪些功能会直接改变现场动作、物料状态和交付决策？

例如：

- SPC 图表本身是输出；
- 超限后的停机、隔离、调整和放行才是业务动作；
- 这些动作需要质量、生产、工艺、计划共同承担；
- 质量要求和结果可以在 QMS 界面呈现，但质量管理过程必须落在真实业务中。

#### 4.5 U9 International 需要确认的内容

现阶段不要直接判断 U9 缺少哪些能力，而应了解其实际配置和使用深度：

- 客户预测和销售订单如何进入系统；
- BOM、工艺路线、工作中心和标准工时是否完整可信；
- MRP 是否真实运行以及如何使用；
- 是否具备粗能力或细能力计划；
- 生产订单如何下达、报工和关闭；
- WIP、批次和质量状态是否可见；
- 库存数据与现场实物是否一致；
- 海外公司、多组织、多币种和跨组织交易如何配置；
- 哪些工作仍依赖 Excel、微信群和人工协调；
- 是否具备有效的接口、数据导出或后续集成条件。

核心问题：

> U9 当前主要是财务和交易记录系统，还是已经成为运营计划与现场执行的基础？

### 阶段三：价值流与未来两年战略匹配

建议时间：30—45 分钟。

使用 `海威价值流_功能标注画板.html`，把讨论从系统模块转到真实业务过程。

#### 4.7 实物流

建议沿以下主线展开：

**供应商 → 收货 → 入库检验 → 仓储 → 材料出库 → 铸造 → 清整/机加 → 装配 → 成品检验 → 成品仓储 → 出库 → 客户**

重点关注：

- 库存和 WIP 在哪里形成；
- 搬运、等待和重复操作在哪里发生；
- 前后工序如何衔接；
- 后工序是否能够拉动前工序；
- 吊具、周转器具、缓冲区和 AGV 是否匹配节拍；
- inbound、过程物流和 outbound 是否被整体优化。

#### 4.8 信息流

建议重点画出：

**客户需求 → 交付预测 → 产能评估 → 生产计划 → 现场执行 → 进度反馈 → 偏差判断 → Replan → 客户承诺**

关键判断：

> 如果只有工单下达和报工记录，却没有滚动交付预测、能力平衡和短周期重排，那么信息流并没有形成完整闭环。

需要确认：

- 客户是否提供预测；
- 海威是否整合预测、正式订单、库存和 WIP；
- 是否能够形成未来数周的交付预测；
- 是否能够识别设备、人员、物料、质量或工序能力缺口；
- 现场偏差多久能够反馈给计划层；
- 谁负责重新计划并更新客户承诺。

#### 4.9 管理流

建议补充第三条流：

**发现偏差 → 判断影响 → 明确责任 → 采取措施 → 验证结果 → 固化标准**

系统只有与管理流连接，数据才会产生实际价值。

#### 4.10 用战略场景验证

分别用以下场景检验现有能力：

1. 宁德项目供货紧张；
2. 墨西哥工厂稳定运营；
3. 罗马尼亚工厂建设和量产准备；
4. 上市阶段的经营透明度和内控要求。

最终需要回答：

> 如果当前规划的系统功能全部上线，它们是否足以支持海威未来两年的增长、客户交付和海外复制？

### 阶段四：识别能力缺口并形成建设路径

建议时间：30—45 分钟。

按照以下完整闭环逐项验证：

**全过程可见 → 偏差识别 → 原因分析 → 管理手段 → 执行改善 → 结果验证 → 标准固化**

对每项功能追问：

1. 它服务哪个业务目标？
2. 输入数据来自哪里，是否可信？
3. 数据偏离后触发什么动作？
4. 谁负责处理，多久完成？
5. 结果如何验证并影响下一次计划？

#### 4.11 可能的计划能力缺口

- 客户需求没有形成统一需求视图；
- 缺少滚动交付预测；
- 计划未与真实瓶颈产能连接；
- 标准节拍和 Performance Rate 未被持续校准；
- 异常反馈后缺少短周期重排；
- 计划与客户承诺之间缺少稳定机制。

#### 4.12 可能的执行反馈缺口

- 计划与实际产出不能及时对比；
- 停机、质量、缺料、人员和物流原因没有统一口径；
- 异常有记录但没有责任、时限和关闭证据；
- 现场数据没有反向校准计划参数和产能模型。

#### 4.13 可能的实物流缺口

- 跨工序 WIP 水位和拉动关系不清晰；
- 物料搬运频率、距离、等待和运力缺少量化；
- 大型产品、吊具和周转器具的操作及防错存在改善空间；
- AGV 或自动化方案可能缺少基于真实节拍和运力的评价；
- inbound、过程物流、outbound、库存和加急成本没有整体考虑。

#### 4.14 可能的管理机制缺口

- 谁判断、谁决策、谁执行、谁承担结果不够清晰；
- 问题升级路径和处理时限不明确；
- 结果缺少验证；
- 改善结果没有固化为标准、参数或系统规则。

#### 4.15 可能的海外复制缺口

海外复制不能只复制软件，还应复制：

- 主数据标准；
- 业务流程；
- 指标口径；
- 组织权限和责任；
- 异常处理与升级机制；
- 系统配置；
- 设备与数据接口规范；
- 培训和审核体系。

以上均属于待验证假设，不应在面谈材料中写成确定结论。

### 阶段五：全过程数据、AI 与未来架构

建议时间：30—45 分钟。

#### 4.16 数据的四层用途

1. **记录事实**
   - 产量、良品、不良、停机、节拍、参数、库存和物流动作。

2. **解释偏差**
   - 判断未完成计划的原因是设备、人员、物料、质量、工艺还是物流。

3. **触发管理动作**
   - 停线或隔离；
   - 调整参数；
   - 调整人员或班次；
   - 调整物料配送；
   - 重新排产；
   - 提前向客户预警。

4. **优化与复制**
   - 校准标准产能与 OEE；
   - 沉淀产品、工艺、设备和参数之间的关系；
   - 形成海外工厂复制模板；
   - 为 AI 建立可信的数据基础。

核心判断：

> 数据采集本身不是价值，数据能够触发什么业务动作才是价值。

#### 4.17 Planning 是动态数据的前提

没有计划基准，设备状态、质量指标和进度数据只能描述现场。

有了计划基准，数据才能用于：

- 判断计划与实际偏差；
- 识别瓶颈和交付风险；
- 调整工序衔接；
- 更新物料拉动动作；
- 触发短周期 Replan；
- 校准后续计划产能。

#### 4.18 AI 的介入位置

AI 不应作为孤立模块提前建设，可以在基础能力形成后介入：

- 设备异常和质量趋势识别；
- 工艺参数相关性分析；
- 有效参数筛选；
- 产能和交付风险预测；
- 异常原因辅助判断；
- 短周期排程建议；
- 海外基地知识复制；
- 设备边缘侧的辅助响应。

核心表达：

> AI 不是系统建设的起点。先有可信数据、计划基准、责任规则和可执行动作，AI 才能真正用于异常识别、参数过滤、计划重排和辅助决策。

#### 4.19 硬件和工厂环境

需要进一步确认：

- 设备是否支持直接采集；
- PLC、传感器和边缘网关的现状；
- 哪些数据必须自动采集，哪些可以人工采集；
- 采集频率与业务动作是否匹配；
- 网络、数据时效和数据存储要求；
- 停线、调参和重排的权限边界；
- 数据采集成本与预期价值；
- 国内方案如何以标准化方式复制到海外。

### 阶段六：投资价值与建设优先级

建议时间：20—30 分钟。

每项系统或数字化投资都应使用以下框架评估：

**业务问题 → 建设内容 → 使用者 → 触发动作 → 经营指标 → 投资成本 → 验证周期**

#### 4.20 可能创造的企业价值

1. **收入与客户价值**
   - 交付更稳定；
   - 缺口更早暴露；
   - 客户承诺更可信；
   - 支持获得更多客户份额。

2. **运营效率**
   - 减少等待、堆积和断流；
   - 减少人工统计和重复录入；
   - 缩短跨部门协调与决策时间。

3. **成本**
   - 降低报废和返工；
   - 降低加急运输费用；
   - 降低库存和资金占用；
   - 降低搬运和无效自动化投资。

4. **风险**
   - 提高质量追溯能力；
   - 提高经营透明度；
   - 支持上市相关治理和内控；
   - 降低海外基地运营失控风险。

5. **能力资产**
   - 形成可以持续运行的计划机制；
   - 沉淀工艺和设备经验；
   - 形成可复制的海外运营标准。

建议表达：

> 每项数字化投资都应明确服务的经营问题、使用者、触发动作和验证指标。否则数据越多、系统成本越高，经营能力却未必同步提升。

不是所有数据都值得采集，也不是所有功能都应同时建设。优先级应由经营影响、实施条件和验证周期决定。

### 阶段七：回到个人价值与加盟方案

建议时间：30 分钟以上。

#### 4.21 个人定位

参考表达：

> 前面的讨论实际上对应我希望承担的几部分责任。我的价值不只是理解系统，也不只是开发工具。我能够从经营目标出发，把供应链计划、现场运营、数据机制和软件工具连接起来，先解决具体业务问题，再形成能够复制的运营体系。

#### 4.22 希望承担的责任

1. **供应链计划与交付协同**
   - 需求整合；
   - 产能平衡；
   - 交付预测；
   - 库存与物流规划；
   - 客户交付风险管理。

2. **数字化运营建设**

   - U9 数据衔接；

   - 将国内验证有效的流程、指标、数据标准和工具形成标准运营包。

#### 4.23 与运营 VP 的可能分工

- 运营 VP 继续统筹制造运营和现场执行；

- 双方共同解决产能、交付和跨部门问题；
- 具体边界需要与董事长对齐，避免形成两套指挥线。

如果需要承担交付改善结果，应同步明确：

- 数据访问权限；
- 跨部门协调权限；
- 异常升级权限；
- 团队和资源；
- 结果责任。

#### 4.24 建议首个试点

选择宁德项目的一条产线或一个产品族，跑通：

**需求 → 交付预测 → 产能评估 → 生产计划 → 实绩反馈 → 异常处理 → Replan**

同时选择一个现场物流或防错问题进行验证。

建议前 90 天：

- **第 1—30 天**：了解订单、流程、工艺路线、瓶颈、现场数据和 U9 使用情况，形成基线和试点范围。
- **第 31—60 天**：建立滚动交付预测、产能评估、计划与实际反馈、每日生产报表和异常跟踪机制。
- **第 61—90 天**：校准计划能力，验证改善结果，完成一项物流或防错试点，并形成下一阶段推广建议。

试点成功标准：

- 能否提前识别交付缺口；
- 计划与实际偏差能否被解释；
- 异常能否推动实际处理；
- 数据是否可靠且采集负担可接受；
- 工具能否被业务人员持续使用；
- 交付、效率、库存或损失是否产生可验证改善。

## 七、交流中的表达边界

1. 不直接评价现有团队“水平低”，改为描述具体业务现象和经营影响。
2. 不把现场一次观察直接推导为系统性结论。
3. 不假设 U9、MES、QMS 或 IoT 已经具备或缺少某项能力，应先了解实际配置和使用情况。
4. 不将 AI 描述为可以绕过基础数据、流程和责任机制的解决方案。
5. 不预先承诺全面上线 APS、替换 ERP 或完成全厂数字化改造。
6. 不把海外备案、规划或客户交流直接写成已经投产或已经定点。
7. 所有改善收益应在建立数据基线后确定，避免提前承诺未经验证的金额。
8. 既展示专业判断，也保留让董事长校正的空间。
