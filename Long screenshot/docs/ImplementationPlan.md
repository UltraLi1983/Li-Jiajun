# 实施计划与验收门槛

状态：Phase 0 完成，以下数值是**预先定义的目标**，不是测试结果；Phase 1 可依据样本证据修订并记录原因。

## Phase 0 — 可行性与架构

交付本目录四份文档，确定首版范围、算法、依赖、风险和验证门槛。当前研究资料以 Apple 开发者文档为主要依据，实际 API 用法须以编译和运行校验。

## Phase 1 — macOS 命令行原型

当前进度：6 个成功合成夹具与 8 个拒绝夹具通过；另有默认降分辨率和全分辨率端到端检查。当前保留的 3 段真实 iPhone 录屏中，2 段输出长图，聊天样本由用户烟测确认顺序正确、未见漏重，但有边缘滚动指示条瑕疵；新替换的无缩放网页样本因图片在滚动中加载，匹配证据不足而明确拒绝。旧的同名缩放录屏仅保留在进度文档中的历史文字记录。派生 1080 px/30 秒负载样本达到性能门槛，详情见 [进度记录](Progress.md)。完整验收仍待更多真实录屏、定量内容标注与复杂动态场景。

1. 建立 Swift Package：`LongScreenshotCore` 与 `longshot`，用 AVFoundation 顺序读取视频帧，输出元数据和抽帧诊断。
2. 实现合成夹具生成器：已知位移的长页面、固定页眉/页脚、停顿、短距离回滚、重复元素、快速跳跃、局部动画。夹具连同真值位移表入库；不放个人敏感录屏。
3. 实现内容 ROI、采样、位移估计、置信检查、条带计划与 PNG 输出。先用合成数据验证，再接入至少 8 段获得使用许可的真实 iPhone 录屏：普通列表 2、网页 2、聊天 1、信息流 1、固定栏明显 1、预期失败 1。真实素材可本地保留，仓库只收匿名化或可公开的样本。
4. 每段输出 JSON 诊断；失败例以非零退出码和明确原因结束。记录命令、Swift/系统版本、输入尺寸/时长、耗时、峰值内存与人工审阅结果。

### Phase 1 验收指标

| 指标 | 初始门槛 | 测法 |
| --- | --- | --- |
| 合成位移误差 | 已知纵向位移的中位绝对误差 ≤ 2 px；95 分位 ≤ 5 px | 与生成器真值逐段比较。 |
| 成功结果内容完整性 | 代表性实录中，人工标注的可见内容缺失或重复总高度 ≤ 输出内容高度的 0.5%；不得有整行文字缺失 | 使用关键行和接缝清单人工审阅，不用单一像素分数替代。 |
| 失败识别 | 所有预设“无重叠/跳页/旋转”夹具必须拒绝；实录中任何明显断点不得被标成成功 | 检查状态、拒绝原因和时间戳。 |
| 几何保真 | 默认等比缩到最多 720 px 后，输出宽度等于处理帧宽度；拼接阶段无额外缩放、透视或插值 | 检查缩放比、条带源矩形与像素抽样；全尺寸模式另验。 |
| 性能基线 | 30 秒、约 1080 px 宽竖屏视频在测试 Mac 上 ≤ 60 秒；峰值内存 ≤ 1 GiB | 用同一输入重复 3 次，报告设备型号和中位数；超标时定位瓶颈，不伪造通过。 |

这些是进入 iOS UI 阶段的目标，不是“任意应用均支持”的承诺。若实录样本不足，Phase 1 只能报告合成数据验证通过，不能宣布总体通过。

当前证据：合成集的 83 对已接受帧，位移绝对误差中位数与 95 分位均为 0 px；派生的 1080 px/30 秒负载在 M1 Pro Mac 上连续 3 次处理的耗时中位数 7.80 秒、峰值常驻内存中位数约 90.3 MiB。聊天实录由用户人工烟测确认顺序正确、未见漏重，但仍缺多类别实录和定量完整性标注，Phase 1 不作总体通过结论。

### 预期复现命令

建好原型后：

```sh
swift test
python3 scripts/verify_fixtures.py --binary .build/debug/longshot
swift run longshot /path/to/recording.mov --output /tmp/longshot.png --report /tmp/longshot.json
```

真实素材按上述类别建清单，记录设备、iOS 版本、应用类型、屏幕方向、视频尺寸、帧率范围、时长、预期成功/失败及人工标注断点。未获授权的第三方内容不入库。

## Phase 2 — iOS MVP（需用户批准后开始）

SwiftUI 导入、进度、预览、导出 Photos、错误详情。验证真机内存、后台中断、取消与大图导出。使用 Phase 1 的同一核心包和夹具。当前 `xcodebuild` 不可用，进入本阶段前要配置 Xcode 与可用设备或模拟器。

## Phase 3 — 系统入口

评估 Photos 分享扩展、App Intents/快捷指令和文件导入。各入口沿用同一导入与处理接口，不把系统录屏自动控制列为验收目标。Apple 当前 iOS ScreenCaptureKit 文档包含需 iOS 27 的预发布示例，只有稳定 SDK 与目标部署版本都满足时再单独研究。

## Phase 4 — 精度与资源优化

根据失败库优先处理动态内容、低纹理、长视频内存和导出兼容性。每项优化必须在固定回归集上比较正确率、拒绝率、时间、内存，不用降低拒绝门槛换取表面成功率。

滚动中图片加载的候选改造见 [DynamicContentProposal.md](DynamicContentProposal.md)。它涉及可回填条带和稳定区域配准，属于本计划约定的重大架构调整；当前仅完成方案，不实施。
