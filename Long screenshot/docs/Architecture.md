# 架构设计

状态：Phase 0 设计；接口和阈值以 Phase 1 实测结果为准。

## 数据流

`本地视频 URL → VideoDecoder → FrameResizer → FrameSampler → RegionAnalyzer → MotionEstimator → StitchPlanner → SegmentRenderer → PNG/Diagnostics`

核心算法以 Swift Package 实现，macOS CLI 与后续 iOS App 共用。平台边界只处理导入、任务调度、预览与导出。处理过程默认离线，不发送视频、帧或报告。

## 模块职责

| 模块 | 输入与输出 | 责任 |
| --- | --- | --- |
| VideoDecoder | 视频 URL → 带时间戳帧 | 验证格式、方向、尺寸，顺序解码；限制同时持有的帧数。 |
| FrameResizer | 解码帧 → 处理帧 | 对宽于默认 720 px 的帧先等比缩小；支持关闭。原视频不转码。 |
| FrameSampler | 处理帧流 → 候选帧 | 分析变化；静止期跳过重复帧，滚动期提高采样密度。 |
| RegionAnalyzer | 多帧 → 内容 ROI、遮罩 | 识别稳定顶部/底部、边缘手势区域与局部动态块；输出不确定区域。 |
| MotionEstimator | 前后帧与 ROI → 位移候选、置信证据 | 在多个纹理丰富的水平带上做纵向匹配，检查残差、带间一致性和位移唯一性。Vision 配准仅作为对照或辅助。 |
| StitchPlanner | 位移证据流 → 片段方案 | 将位移累计为内容坐标；处理停顿和短暂反向滚动；仅追加已验证的新内容，遇断点停止。 |
| SegmentRenderer | 处理帧片段 → PNG | 只裁切和拼接，不做额外几何变形；未来优先分块/分段，避免保留完整长图位图。 |
| Diagnostics | 每一步证据 → JSON/文本 | 记录时间戳、ROI、位移、误差、置信度、拒绝原因，不存原始敏感像素。 |

## 拼接决策

1. 第一帧建立基准坐标。计算每对相邻候选帧在可滚动 ROI 内的位移，要求至少三个空间分离的有效带；阈值为 Phase 1 待校准参数。
2. 用候选位移计算重叠区域的鲁棒像素误差。若位移接近零，记为停顿；若向下滚动，则只追加新进入视口的底部原像素；反向滚动时先更新坐标轨迹，不重复追加旧区域。
3. 每个新增条带保存来源帧和源矩形，直到渲染。固定栏只在首帧或最终组合中保留一次；其裁切范围由检测结果给出，并记录在报告中。
4. 对高速滚动、低纹理、重复行、动态遮挡和内容重排设置独立拒绝原因。跨断点默认不生成貌似连续的长图；可输出已经验证的前缀和问题位置供用户检查。
   单个低置信度候选帧允许短时跳过，但后续帧必须与最后一个已验证帧直接通过位移和重叠检查；持续不确定时拒绝整段。
5. 视频内如果存在多次独立滚动、页面切换或横向滚动，Phase 1 直接拒绝。将来可扩展为分段结果，但必须有明确边界。

## 内存与输出

当前 Phase 1 原型为单遍读取，默认把大于 720 px 宽的已解码帧缩小后再匹配、裁切和拼接。原视频不改动；这不会降低原始解码负担，也会损失文字细节。每个裁切条带深拷贝后保留，末尾构建完整画布；真实 592 × 1280 视频峰值常驻内存约 94 MiB。1080 × 2336 缩放负载原尺寸处理约 190 MiB、12.29 秒；内部缩为 720 px 后约 86 MiB、8.29 秒。极长输出仍可能超限，届时改为条带式 PNG 写出或分段导出。单图像素数按 `width × height × 4` 估算未压缩内存，另计视频解码缓存和编码器缓冲。绝不只依据压缩后的文件大小判断安全。

## 依赖与接口

- 语言：Swift；标准库、AVFoundation、Core Video、Core Graphics、Image I/O、Accelerate / Vision（按实验结果选用）。
- 无云端服务、无私有 API、无付费依赖。OpenCV 为备选研究项，需有对比数据后才提议引入。
- CLI：`longshot input.mov --output output.png --report report.json [--max-width pixels]`；默认 720，0 保留原始分辨率。非零退出码表示不支持、证据不足或处理失败。
- 诊断报告包括 `status`、`reason`、`input` 摘要、`framesExamined`、每段的时间与位移、重叠评分、输出尺寸、耗时、峰值内存（可获得时）。报告版本化，避免把文件绝对路径或图像内容写入可分享报告。

## 决策记录

- ADR-001：优先垂直平移模型和原像素裁切。理由：清晰可解释，避免几何失真；代价：复杂页面会被拒绝。
- ADR-002：核心做成可在 macOS/iOS 复用的 Swift Package。理由：命令行验证后可直接接入 SwiftUI。
- ADR-003：默认失败关闭。无法证明连续性的片段不得悄悄拼入。
- ADR-004：默认将宽于 720 px 的解码帧等比缩小，保留 0 选项输出全尺寸。理由：目标主要在手机查看，测试负载的时间和内存下降明显；不预转码，避免导入延迟与额外文件。后续以原生高分辨率样本核验小字可读性。
