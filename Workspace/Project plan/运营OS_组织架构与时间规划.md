## 二、前 3 个月组织架构（Phase 1：审核系统）

### 2.1 组织架构

**核心任务**：模块库从零建设 + 首客户交付验证。前 2 月创始人+用友专家直接配合做产品——创始人独揽 VDA+PM 双角色，无需中间翻译层。第 3 月 IE+实施加入组成交付三人组。

**关键判断**：
- **PM 由创始人兼任**：前 3 个月仅 1 个客户，审核专家最懂 VDA 需求，从审核检查项 → 产品原型 → 现场配置一条线贯穿，不需要独立 PM 做翻译。第 2 个客户起（第 4 月）再招独立 PM。
- **IE 第 3 月进入**：IE 的现场标定必须基于具体客户的工艺现实——没有客户时做"抽象模块库设计"是凭空设计。且精益/运营优化的价值在 Phase 2 才体现（客户有意愿购买持续服务时），Phase 1 是 VDA 合规验证——创始人对 VDA 数据采集需求足够清楚，硬件伙伴能判断采集可行性。IE 第 3 月带着首客户的具体工艺进场做标定，事后用首客户真实数据反哺模块库标准化。

```
                      [ 核心大脑/决策层 ]
                (创始人 + 用友开发专家)
                          │
     ┌────────────────────┼────────────────────┐
     ▼                    ▼                    ▼
【专家+需求+交付】     【模块开发组】        【硬件协同】
 负责人：创始人         负责人：用友开发专家    外协硬件伙伴
 (VDA+PM 双角色)       ├─ +后端开发(2人)     （非全职，按需进场）
  ├─ +IE工业工程师     └─ +前端开发(1人)
  │  (第3月进入)
  ├─ +实施顾问
  │  (第3月进入)
  │
  首客户交付阵容 =
  创始人(VDA诊断+验证+PM配置+培训)
  + IE(现场标定+数据验证, 第3月)
  + 实施顾问(全程跟学+交接, 第3月)
  → 仍为三人组，PM 职责由创始人承担
```

### 2.3 各角色 3 个月任务矩阵

### 2.4 关键提醒

- **PM 由创始人兼任（前 3 个月）**：审核专家最懂 VDA 需求，从审核检查项→产品原型→系统落地一条线贯穿，不需要 PM 做翻译。创始人直接与用友开发专家对接，沟通零损耗。第 4 月（第 2 个客户起）再招独立 PM。
- **IE 第 3 月进场**：IE 不做抽象的模块库设计——那是凭空画图。IE 拿着首客户的具体产线进场，标定真实的数据采集点、写出真实的 SOP、产出真实的标准化模板。事后用首客户数据反哺模块库。且精益/运营优化的价值在 Phase 2 才体现（客户有意愿购买持续服务时），Phase 1 仅做 VDA 合规验证，创始人对数据采集需求足够清楚。
- **AI 算法工程师**：Phase 1 不需要。审核系统用规则引擎，第 4 个月再招。
- **第 3 个月必须新增 1 名实施顾问**：创始人不能永远是实施负责人。此人跟完第一个项目全程，第 2 个客户起独立带队。
- **运营 OS 开发不暂停**：底层架构（数据管道、事件总线、微服务边界）两阶段共用，Phase 1 就为 Phase 2 留好扩展接口。
- **从第一天就以产品化思维建设**：每个工艺模块必须做到"可配置、客户可选配"，不能走"每个客户定制一套"的老路。首客户是验证场——验证的是模块的可复用性，不是验证"我们能交付"。
- **招聘原则**：熟人优先。3 个月时间太短，从各自圈子里"摇人"。但前 2 月不急着招人——先把产品方向吃透。

## 三、6 个月组织架构（Phase 2：模块库成型 + 多客户）

### 3.1 背景

- 第 4-6 个月，首客户审核系统稳定运行，运营 OS 开始加载
- 客户 2、客户 3 陆续接入
- 模块库已有 3-5 个工艺包（压铸/机加工/装配为首批，按客户需求追加）
- 交付模式已切换为"选配+微调+验证"——实施顾问开始独立执行标准交付
- 产品与交付的边界清晰：开发做模块，交付做配置


## 四、1 年组织架构（规模化运作）

### 4.1 背景

- 第 7-12 个月，5-8 家客户
- 模块库覆盖主流工艺类型（8-10 个工艺包）
- 审核系统为成熟产品，运营 OS V2.0 运行中
- 交付高度标准化：实施顾问独立执行，专家远程验证
- 客户接入边际成本持续降低（第 3+ 客户 ~15 人天/个）

## 八、单客户交付人员配置与任务分解（人/天）

> **目标企业画像**：压铸 + 机加工 + 装配工艺线路，年产值约 10 亿 RMB，当前使用国产 ERP。
>
> **交付模型**：**产品化交付，非项目制开发。**
> - 审核专家带入业务，提供**成型的运营模块库**供客户选择。
> - 现场工作 = 模块选配 + 微调 + VDA 合规验证。
> - 模块库中缺少的工艺类型 → 产品侧加速开发（不拖交付节奏）。
> - 客户已有模块上的特殊要求 → 在原有模块基础上做配置级改动。
>
> **工作量口径**：以下人天仅计客户现场的交付活动。产品研发（模块库建设、新工艺包开发）不计入。

### 8.2 标准交付：人员配置与任务（全模块就绪场景）

**前提**：压铸包、机加工包、装配包已在模块库中。审核系统已产品化。

> **首客户（客户 1）**：创始人独揽 VDA + PM 双角色。第 2 客户起独立 PM 到岗，创始人回归纯 VDA 咨询师。

| # | 角色 | 人天 | 在场时段 | 做什么 |
|:--:|------|:--:|------|------|
| 1 | **VDA 主咨询师 + PM**<br>（创始人，首客户双角色） | **10-12** | W1-W2 全周 | **VDA 部分**：① 走线诊断，对照 VDA 标准评估现状（1.5天）② 确定适用模块，将每个模块映射到具体工艺节点（1天）③ 识别客户特殊要求，输出微调要点（0.5天）④ 最终 VDA 合规验证（1.5天）⑤ 向客户管理层做交付总结（0.5天）<br>**PM 部分**（与 VDA 流程自然衔接，无沟通损耗）：⑥ 根据 IE 标定结果在系统中配置客户化参数（2天）⑦ 处理客户特殊工艺微调：加规则/改阈值/调流程（1-2天）⑧ 客户基础数据导入与校验（1天）⑨ 分角色培训：操作工/班组长/质量/管理层（1.5天）⑩ Go-live 首日全程在场（1天） |
| 2 | **IE 工业工程师**<br>（第 3 月招） | **5-6** | W1 全周 + W2 | ① 现场数据源盘点：设备 PLC 型号/协议、现有传感器、信号死角（1天）<br>② 模块映射到物理现场：每个规则需要的采集点是否可实现（1.5天）<br>③ 协助创始人做客户化参数标定：阈值、频率、容差（1天）<br>④ 配合创始人做证据链验证（1.5天） |
| 3 | **PM / 业务分析师**<br>（客户 2+：独立 PM 到岗） | **7-8** | W1-W2 全周 | ① 根据 IE 标定结果，在系统中配置客户化参数（2天）<br>② 处理客户特殊工艺要求的微调：加规则/改阈值/调流程（1-2天，如有）<br>③ 客户基础数据导入与校验：物料、BOM、工艺路线（1天）<br>④ 分角色用户培训：操作工/班组长/质量/管理层（1.5天）<br>⑤ Go-live 首日全程在场（1天） |
| 4 | **硬件外协伙伴** | **5-8** | W1-W2（如需） | ① 车间勘查 + 施工方案（1天）<br>② 传感器/读头/网关安装（3-5天）<br>③ 硬软联调（1-2天） |
| 5 | **实施顾问** | **7-8** | W1-W2 | ① 全程跟创始人和 IE，学习业务与系统（3天）<br>② 协助培训 + 数据初始化（2天）<br>③ Go-live 后接手，成为客户主接口人（2天）<br>④ 退场后：远程维护 + 按需短驻（约 2 天/月） |

### 8.3 两种例外场景

#### 场景 A：模块库缺少某工艺类型（如客户有热处理，库里没有）

| 处理方式 | 人天 | 说明 |
|------|:--:|------|
| **不影响标准交付** | — | 已有的压铸/机加工/装配包照常部署。缺失模块不阻塞审核——VDA 审核针对的是客户全部过程，未覆盖的工艺段由专家出具人工管理方案，审核时以文档+人工证据补位 |
| **产品侧加速开发** | ~15-20 天 | IE 定义规则 + PM 输出需求 + 后端开发 + 前端看板。**这是模块库建设，不计入该客户交付人天** |
| **事后补装** | 2-3 天 | 模块开发完成后，PM 远程配置 + 1 天现场验证即可上线 |

#### 场景 B：客户已有模块的工艺有特殊要求

| 改动类型 | 人天 | 谁做 | 举例 |
|------|:--:|------|------|
| **配置级**（改参数/阈值/频率） | 0.5-1 天 | PM 现场配置 | 客户 CNC 品牌不同 → 改 OPC-UA Tag 映射表；客户检验标准更严 → 改 SPC 控制限 |
| **规则级**（加判断逻辑/加检查项） | 1-3 天 | PM 写规则 + 后端远程支持 | 客户在压铸后多一道"浸渗"工序 → 加一条追溯规则；客户要求装配扭矩按产品型号区分不同标准 |
| **代码级**（改模块底层逻辑） | 3-5 天 | 后端远程开发 + 1 天现场部署 | 罕见。优先通过配置和规则层解决，尽量不动代码 |
