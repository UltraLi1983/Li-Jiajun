## 目标与边界

- 在四阶段排产流程之外提供独立的“工艺库”入口。本地建档用于前置系统缺位时维护可复用工艺定义，不依赖先选择产品或创建路线副本。第一阶段只从工艺库选工艺加入本地验证路线，仍是另一个动作。
- 工艺类型与具体工艺分开。类型从稳定受控清单选择，允许显式新增本地类型；不能靠每次在工艺表单中自由输入一个新类型字符串。已有 `machining`、`assembly`、`qualityGate`、`packaging` 和本机新增类型的 ID/引用不丢失。
- 工艺身份采用稳定内部 `processId`，新建时由系统生成且校验唯一；操作者输入名称、类型，可选说明和企业业务编号。来源、状态、初始版本、创建时间由系统记录。业务编号、外部系统 ID 与 `processId` 不混用。已存在的 `processId` 原样保留，不因迁移或改名重写路线引用。
- 保存工艺仅使其进入工艺库，不自动插入产品路线，不创建工站/执行单元，也不填 CT、每循环件数或 P/Q。新增工艺仍是本地草稿；正式校验继续拒绝草稿工艺和路线。已发布样例与上游数据只读。
- 本包不实现 ERP/项目系统 API 导入、工艺审批发布、全新产品创建、物理设备主档、`OP10-1` 等稳定执行单元、设备换绑或按设备重算。字段可为未来来源映射预留，但不制造“已同步上游”的假状态；上述后续内容按架构文档另包实施。

## 实施任务

1. **身份与类型**：建立工艺类型的稳定 ID/显示名与本地来源记录，复用现有类型值而不强制改写样例。工艺库新建操作生成不可变内部 `processId` 和初始版本；名称、类型必填，说明与企业业务编号选填。同名或相似名称给出重复提醒，不仅凭名称自动合并，也不硬性拒绝合法同名工艺。业务编号若录入，校验本地命名空间内的冲突。
2. **独立工艺库界面**：在四阶段导航之外增加“工艺库”入口，清单可查看编号、名称、类型、来源、版本、状态和路线引用情况；支持搜索、查看、新增本地工艺与本地类型。创建后能回到原排产页面和原产品/路线/工站上下文；不强迫先建验证副本。第一阶段原“新增工艺”表单改为进入工艺库或复用同一建档交互，不维持两套不同创建逻辑。路线上“添加工序”仍只处理工艺选择、顺序和路线引用。
3. **来源与未来映射**：保留现有 `sourceSystem`、状态和版本语义，新增本地记录明确标记本地来源。若预留 `externalProcessId`/外部版本等字段，应与来源系统成对使用，且不得用外部 ID 替代内部 ID；本包不提供可伪造正式导入状态的手工输入。已引用工艺改名或类型变更不能静默改写已发布路线和历史结果；本包可以只提供查看、新增，不必交付编辑/合并/删除。
4. **存储与兼容**：迁移本地存储时保留任务包 15 已建立的工艺、路线、工序及其 `processId` 引用；刷新可恢复。若更改 schema version，明确版本升级和旧数据回退/错误提示，不以清空旧存储作为迁移。工艺库数据与本地验证路线的清除范围要明确：不能把“清除验证路线”误做成无提示删除整个可复用工艺库，也不能让悬空引用进入路线。
5. **正式门禁和文案**：本机工艺草稿可用于本地试算，但不因进入工艺库而成为正式已发布主数据。页面用短文案区分“本地工艺”“路线工序”“物理设备”，不把 `processId` 称作设备编号。中英文标签和窄屏布局保持现有应用风格。

## 自动验收

- 建立本地工艺不依赖先选定或创建产品路线；即使页面已有默认产品，创建前后四阶段选中上下文也不变。新建工艺只增加工艺库记录；显式选入本地路线后才增加 `Operation`。
- 同一工艺能被两个本地验证路线复用；重复提醒不错误合并；`processId` 稳定且唯一，类型 ID 稳定，企业业务编号与外部 ID 不冒充主键。
- 已有任务包 15 的本地存储升级后，路线 `processId`、顺序和参数引用仍有效；刷新后工艺仍在。已发布样例不变，正式预检仍拒绝草稿工艺/路线。
- 覆盖缺名称/类型、相似名称、业务编号冲突、新增类型、刷新/迁移与清除边界；浏览器回归真实操作，不只检查渲染字符串。运行 `npm run check`、`npm test`、`npm run build`，并按 `safe-html-preview` 做界面检查。交付时只报告实际跑过的验证与残余风险。
