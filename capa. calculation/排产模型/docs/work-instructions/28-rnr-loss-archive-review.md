# WI-28｜R&R 的 ML 损失核对与本地样本归档

## 使用范围

此流程只形成**本地内部试算证据**。当前没有账号和授权审核系统，样本归档、损失采纳及报告快照均不代表正式验收通过。

## 人工核对步骤

1. 在项目验证流程选择产品、路线、工序及工站。到阶段 3「现场 R&R」核对实际生产、异常、休息、换型、保养、计划停机各段的真实起止时间，补齐缺口。确认数据来源不是「加载 R&R 验证样本」。
2. 到阶段 4 的工站明细，查看「异常证据与推断损失」。若确认可以在未来排程中补救某段损失，填写可补救分钟并点击该行「确认」；零分钟也不代表异常损失已被采纳。
3. 查看「ML 的 SA 损失确认」。逐段决定异常是否进入 ML；计划动作超时按类别确认。系统只计侵入原计划生产的分钟。点击「确认纳入 ML」后，核对已确认额外损失、待确认分钟及源窗口损失率。
4. 查看「提示清单 · 总时间一致，时段错位」。休息、换型、维护保养和计划停机逐类比较：同类总分钟相同但发生时段不同时，系统单列错位分钟及「待人工确认」；核对后点击「确认总量一致」。这不增加超时 SA 损失，也不抹去逐段状态差异。时段或计划修改后，原确认失效；超时与异常损失仍在上方单独确认。
   若同类实际总分钟短于计划，系统仅在「实际计划动作短于计划」清单提示，无确认按钮；不自动增加 ML 产能，也不拿缩短分钟抵扣其他损失。
5. 到「R&R 独立样本归档」填写物理设备编号，点击「归档为新样本」或「保存当前样本修订」。确认区应显示当前确认已包含在样本修订中；若显示修改待保存，当前决定还未归档。重开该修订，再核对损失分钟和错位确认状态。
6. 返回阶段 2 或阶段 4 的周能力报告，核对复制日与平稳日的 ML 生产分钟。平稳日只采纳它已设动作对应的超时损失；生产中的已确认异常始终参与。周报告仍按**当前工站草稿**计算，选择归档修订目前只提供同窗证据，不能当作自动切换周 ML 依据。

## 当前本地数据核对结果（2026-10-26，只读检查）

- 本地数据库是 `state.sqlite3` 的键值存储；R&R 当前草稿和独立样本修订均以 JSON 保存。每个实跑事件可保存损失采纳标记、计划签名、采纳时间，以及可补救分钟的确认标记和时间。旧数据没有确认时间，不能追补成已确认。
- 当前路线已生成周账的工站为 OP10、OP20A、OP20B、OP30。OP10 有 3 个平稳日，休息、换型、保养、计划停机分钟均为 0；OP20B 有 3 个平稳日，休息 120 分钟，其余三类为 0；OP20A 与 OP30 没有平稳日。
- 当前路线的 R&R 草稿均标记为**验证样例**，尚无 `mlLossConfirmed` 的已采纳事件。独立样本归档只有 OP10 的 2 个修订，二者同为验证样例。不要把它们标记为真实跑线证据或正式资格样本。
- 同名 OP10 存在不同工序上下文的本地草稿。归档前必须核对路线版本、工序、工站及物理设备，避免把另一个工序的草稿当作当前 OP10。

## 目前不能完整归档为正式依据的内容

| 缺口 | 当前状况 | 后续处理 |
| --- | --- | --- |
| 真实 R&R 证据 | 当前归档是验证样例，不能人工改标成真实 | 新建真实样本并录入现场时间段、产量与证据来源 |
| 确认人及授权 | 本地保存确认时间，不保存已认证账号/角色 | 账号与审核系统上线后绑定确认人与权限；之前只作内部核对 |
| 独立损失决定版本 | 决定嵌在实跑事件的 JSON 中，可随样本修订保存；没有单独可发布的损失参数账 | 建立样本修订、损失率、适用周和生效规则的受控版本 |
| 归档样本驱动周 ML | 报告选择样本只影响同窗证据；周 ML 读取当前工站草稿 | 完成资格检查与受控引用后才能切换预测依据 |
| 平稳日动作匹配历史 | 当前周账有动作分钟和逐日 ML 结果，但尚无单独的逐日“采用哪条损失决定”归因记录 | 在正式报告快照中加入逐日来源与损失分类引用 |

不要直接改 SQLite 或浏览器存储中的 JSON 来伪造确认。旧样本需要修改时，通过界面重开并保存新修订，旧修订保留。
