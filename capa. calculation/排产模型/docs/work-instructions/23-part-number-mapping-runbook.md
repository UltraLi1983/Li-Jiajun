# 临时零件号与企业零件号映射工作指导书（草案）

## 1. 目的与边界

在目标企业编号规则尚未确定时，先以本系统生成的临时零件号开展项目验证；接入企业的受控物料主数据后，建立可追溯的对号关系，不重写已有路线、BOM、R&R 和历史报告。

本指导书只处理**零件身份及编号映射**。它不证明物料可互换，不生成 WIP 库存，也不替代工艺、路线、BOM 的发布审批。PV-02 对阶段物料/WIP 的检查，应引用有效的受控资料；仅建立一条本地映射，不得自动解除正式发布门禁。

## 2. 三种标识

| 字段 | 用途 | 变更规则 |
| --- | --- | --- |
| `partId` | 系统内部主键，供所有记录关联 | 创建后不变、不复用，界面可隐藏 |
| `temporaryPartNo` | 项目验证期可见编号，如 `TMP-000123` | 不改写、不回收；企业号到位后保留为历史别名 |
| `externalPartNo` | 企业在指定系统和组织下使用的零件号 | 通过版本化映射关联，不覆盖 `partId` 或临时号 |

英文零件名称是必填描述，可用于提示候选项，**不能单独作为自动对号依据**。产品、半成品和每个需独立追踪的 WIP 状态分别建号。相同企业零件号若覆盖多个工序状态，须以产品、路线版本和工序/阶段明确区分；无法唯一识别时继续使用内部 WIP 号并暂停该条自动对号。

## 3. 接入前准备

目标企业须明确一个物料主数据权威来源（例如受控 BOM/PLM/ERP），以及其生效和失效口径。每批资料应保留来源系统、文件/批次编号、资料版本、导出时间、批准证据和原始文件校验值。未确认权威来源的资料只能用于预览或本地试算。

首次导入至少准备四类记录：

| 记录 | 最小字段 |
| --- | --- |
| 零件主数据 | 企业/租户、来源系统、组织/工厂、企业零件号、英文名、物料类型、版本、状态、生效/失效时间 |
| 编号映射 | `partId`、临时号、企业零件号、来源系统、组织/工厂、适用产品及路线版本、工序/阶段（需要时）、生效/失效时间、状态、证据引用 |
| 工序物料关系 | 产品及路线版本、工序、方向（投入/产出）、零件号、每件数量、单位、上游来源工序、BOM 版本及生效时间 |
| 工程变更关系 | 旧零件号/版本、新零件号/版本、变更单、变更原因、生效时间、可互换性结论及批准证据 |

接口字段可扩展，但不可省略来源、版本及生效时间。导入时保留原始编号；空格、大小写、前导零等标准化规则须按企业逐一确认，不能默认改写。

## 4. 首次对号流程

1. **收件与暂存**：保存原始资料和来源证据，校验字段、状态、版本、有效期及重复行；此时不更新正式映射。
2. **生成候选**：优先用“企业 + 来源系统 + 组织 + 企业号 + 版本 + 生效时间”定位；结合已确认的产品、路线和工序物料关系，筛出可能的 `partId`。英文名只辅助人工核对。
3. **分类处理**：唯一且资料一致的进入“待确认”；缺号、错路线、有效期冲突、同号多义或多候选的进入“待处理”，列明原因和涉及工序；不得任取第一条。
4. **核对批准**：主数据责任人核对物理零件身份、工序状态和工程变更；受控资料批准人确认来源版本。当前尚无账号/角色系统时，记录外部批准证据，系统内仅标“待审核/本地试算”，不得把手填姓名视为正式授权。
5. **激活与复核**：未来具备授权机制后，批准的映射按生效时间激活；确认同一适用范围内没有相互冲突的有效映射，抽查路线首末工序及并行工站。显示可优先用企业号，历史记录仍按 `partId` 与当时版本还原。

一个 `partId` 可以有不同来源系统中的多个别名；同一来源范围和同一时刻的企业号若指向多个 `partId`，必须存在足以唯一判别的上下文，否则禁止自动入账。

## 5. 日常导入与自动化

文件导入和未来 API 对接使用同一暂存、校验、确认、入账流程。已确认且仍有效的映射可自动匹配；新号、改号、版本变化或歧义项进入异常队列，等待核对。每次处理保存批次 ID、来源记录 ID、原始值、匹配规则版本、结果和操作记录。重复导入同一批次应幂等，不产生重复零件或映射。

下游交易按**事件发生时间**查找当时有效的映射；晚到数据不能套用今天的新号。失败记录保留原始数据并隔离，不能悄悄改归其他零件。映射纠错采用新增修正记录及失效旧记录的方式，历史结果重算须另行申请并留痕。

## 6. 工程变更及特殊情形

| 情形 | 处理办法 |
| --- | --- |
| 同一零件号仅修订图纸/属性 | 维持 `partId`，增加受控版本及生效区间；是否影响库存可用性由工程结论确定。 |
| 新零件号代表不同物理件或加工状态 | 新建 `partId`，建立前后继关系；旧库存、实绩、报告不自动并入新号。 |
| 企业没有独立 WIP 号 | 保留系统唯一 WIP 号，并以受控产品、路线、工序/阶段作映射上下文；有歧义则禁止自动匹配。 |
| 企业复用同一号码 | 增加来源系统、组织、版本和生效时间判别；仍无法唯一定位则隔离并请企业主数据责任人裁定。 |
| 临时号对错 | 失效错误映射、建立修正记录及影响清单；不删除原始来源和历史交易。 |

工程更改的可互换性、旧料处置和切换日期必须来自获批变更单，系统不得凭名称相似或号码相邻自行推定。

## 7. 验收清单

- 正向：同产品、同路线版本和有效期内，前工序产出号与后工序投入号能唯一衔接，PV-02 仅在受控引用有效后清除“阶段物料/WIP”阻断。
- 反向：缺引用、错产品/路线、过期、工序不衔接及一号多义，都显示具体工序和原因；草稿工艺/路线各自门禁仍保留。
- 重导：相同批次不增加重复记录；失效映射不被新交易使用，历史报告可按当时映射重现。
- 边界：映射不改库存，不跨零件号自动转移旧 WIP，不把 Demo 物理库位数据当作正式库存。

## 8. 示例

`TMP-000123`（OP10 产出/OP20 投入的同一 WIP）对应企业 `E-4721`。确认受控 BOM 版本和生效时间后，保留原 `partId`，新增映射；界面显示 `E-4721`，旧数据仍可检索 `TMP-000123`。若工程变更后形成**不可互换**的 `E-4722`，应新建 `partId`，记录 `E-4721 -> E-4722` 的变更关系，而不是把旧号改写成新号。

## 9. 实施顺序

先落地只读对号预览和异常清单，再增加受控证据、确认与映射账，最后接入企业 API 和自动同步。正式启用前，还需确定目标企业的权威系统、组织/工厂编号范围、版本规则、批准责任人与工程变更流程；这些不能由当前草案代替。
