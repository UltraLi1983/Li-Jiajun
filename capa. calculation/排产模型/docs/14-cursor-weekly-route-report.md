## 业务口径

- 报告用于内部排产决策，A4 纵向两页：上周回顾、下周计划。相同产品/路线、相同指标顺序与同一件数横轴刻度，方便逐项对照；标题、周期和数据状态清晰区分。Most likely（ML）是排产计划线，同时是未来产出的预测；Best case 是挑战线，不是默认排产目标。
- 回顾页列需求、ML 计划、已发生 Actual、Best，以及各工序计划/Actual/Best 和瓶颈；OP20 等关键工序的 SA/P/Q 分别列计划与实际。Actual 只来自对应已发生周期的完整真实记录。R&R 只跑了 48H，不能直接当作整周实绩，也不能按比例扩成整周 Actual；缺少完整周期/工站数据则 Actual、实际瓶颈和实际差额留空，并指出缺口。
- 下周页列需求、ML 计划、Best、计划瓶颈和计划余量。尚未发生的 Actual 卡片、图表、工序表、SA/P/Q 实际列均留空或显示 `—`；不得把 ML 数字复制到“结果/预测/Actual”列。计划余量 = ML 路线成品件数－需求，不称实际余量。两页都不把能力直接称作可交付量；不推断库存或在途。
- 计划件数来自各工站同一目标周的有效日历/周账、当日生效的已发布 CT/每循环件数/P/Q、Most likely 按班次预留。先算各工站，再合并同工序并按该工序每成品所需件数换算，最后取路线串行瓶颈。工站占用份额是否进入周综合排产必须沿用领域模型现有规则并在报告中说明；绝不能悄悄沿用 48H 同窗 100% 上限。周计划来源不全、版本未生效、用量缺失或换算不合法时，路线周计划留空并列出缺失工站/工序，不用 0 或样例数填充。
- 参数版本不同的日子分别计算后汇总。Best case 件数不乘 P/Q；ML 件数只乘当日已发布生效的 P/Q 一次。标准 SA 时间账不因 CT/P/Q 改变。回顾页计划应使用该周排产时的快照，不用今天的新参数重写历史计划；若没有可信历史快照，就明确标成“当前参数回算”，不能冒充原计划。
- 无计划 CT 的初始本地预设，P 输入默认 100%。操作者可改为大于 0 且不超过 100% 的数值；非默认值须提示它是人工判断、尚非时间窗实跑推导，并再次明确确认后写入，不硬性拒绝。保存实际输入值、人工覆盖来源及确认信息，参与生效后的计划件数计算；取消确认则不写入。P 不能从节拍样本均值自动猜出。已有计划 CT 的矫正路径保留当前“无时间窗则 P 保持，有时间窗则按新 CT 重算 P”的口径。

## 实施顺序

1. 在第三阶段“建立本地初始预设”加入 P (%) 输入，默认 100%。输入其他有效值时，提交前显示明确提示并做第二次确认；取消不写入，确认后保留人工输入值及覆盖标记/确认信息。`establishInitialLocalPreset` 继续接受经过显式复核的有效 P，但要校验 0 < P <= 1；非默认值不能只靠现有 `performanceReviewed: true` 绕过，需单独的覆盖确认输入并写入来源。核对 UI、导入/恢复及直接调用方。默认 100% 的普通确认流程保持简洁。不要改已有 CT 的矫正逻辑。
2. 建立纯函数的路线周计划汇总层，消费现有周账/周件数、工站参数版本和工序用量；输出各工站、工序、路线的 Best/ML 件数、版本/来源、缺口原因、计划瓶颈与需求余量。对部分缺失采用不可计算状态；不要把各站不同目标周、不同产品或不同路线的数据拼在一起。先核对既有周账能否为每个可排产工站独立保存/读取；缺失这条链路时先补齐它，不伪造输入。
3. 定义内部报告快照/视图模型，明确目标周、生产日锚点、计划版本、数据来源与计算口径。回顾与下周页读取各自独立的周计划，不共享一份动作损失；允许同一 CT/P/Q 下周 SA 和件数不同。Actual 仅在完整周期证据可用时写入；目前本机每工站只有一份草稿，不能假称它是历史整周归档。可先以“未提供完整实绩”呈现空态，正式多次 R&R 归档另包开发。
4. 把 A4 双页报告接入正式界面，提供“查看/打印 PDF”入口。以 `report-preview.html` 为布局参考，但所有正式数值都须来自视图模型；演示样本不得自动进入报告。两页保留需求/计划/Actual/Best、工序表、SA/P/Q、周期补充信息和口径/来源。数值为整数件，百分比与 CT 单位明确；屏幕和打印均避免跨页截断、横向溢出。报告只作内部决策，不提供发布到客户的功能。
5. 更新工程计划、README、人工烟测手册和本包状态。别提前标“正式已完成”；本地报告/计划快照的生命周期及历史归档缺口要明示。

## 自动验收

- 初始预设 P 默认 100%；人工改为 90% 时先提示“非实跑推导”，取消二次确认则不生成版本，确认后版本保留 90%、人工覆盖来源及确认信息。引擎拒绝越界 P、缺少显式复核的非默认值；已有 CT 矫正 P 的测试继续通过。周/月计划件数按最终有效 P 计算，标准 SA 时间账不变。
- 两个连续周：相同 CT/P/Q，第一周与第二周换型/班次不同，ML 件数不同；参数在周中生效时逐日取版本。Best 不乘 P/Q，ML 只乘一次；周账分钟不变。
- 同工序双工站合并、跨工序用量 1 与 2、瓶颈/需求余量；缺站、缺周账、版本失效、用量缺失、目标周不一致时报告不显示路线数值，并说明原因。
- 回顾页：仅 48H R&R 而无完整周实绩时 Actual 全部留空；有完整且同周的实绩输入时按证据填 Actual。下周页所有 Actual 保持空白，ML 只出现于计划线；不出现“结果预测 = ML”。历史计划无快照时须标“当前参数回算”。
- 中英文、窄屏、A4 打印、工序/工站切换与刷新后来源隔离。浏览器交互回归必须真实进入报告并核对可见内容；不能只用源码字符串断言。遵循 `safe-html-preview`：优先应用内浏览器，不从终端启动系统 Chrome；无法视觉检查时如实说明。
- 运行 `npm run check`、`npm test`、`npm run build`，记录通过数量与未覆盖风险。

## 人工烟测 5.15（待用户执行）

1. 在无计划 CT 的工站建立初始预设：P 默认 100%；手改为 90% 时看到“人工判断、非实跑推导”提示，取消二次确认不生效，确认后版本和周/月 ML 件数使用 90%，标准 SA 不变。然后让两个周分别设不同排班/换型，CT/P/Q 保持一致：报告两页的 SA、ML 件数和计划余量应随周变化；Best 作为独立挑战线。
2. 只保留一站 48H R&R，打开回顾页：实际结果、实际瓶颈、实际 SA/P/Q 缺证据处为空，明确写出缺失；不能以 48H 推整周。下周页的所有 Actual 仍为空。
3. 给各工站准备同一周的完整计划，核对工序用量 1/2、并行工站合并、路线瓶颈；删除一个工站计划后，路线数值留空而其他站原单位结果仍可看。
4. 查看屏幕和 A4 打印/PDF：两页对齐、横轴刻度相同，数字与单位不挤压，分页不切断表格；未发布 CT/P/Q 不进入报告。完成后由用户确认，不以自动测试代替。
