## 目标与边界

- 在第一阶段增加明确标识的**本地验证模式**，让操作者为已有测试产品创建可复用的 `ProcessMaster`，从工艺清单选择它加入该产品的一条本地验证路线，形成独立 `Operation`，再分配工站、维护参数并进入标准 SA、R&R 与产能预检。新增工艺和新增路线工序是两个动作，ID、版本、来源和生命周期分开。
- 已发布样例/上游路线不能就地改写成验证路线。对已有产品创建独立的本地路线副本，使用新 `routeId`、`draft` 状态和 `local-validation` 来源；保留原路线可选。页面顶部和路线选择器持续显示“本地验证”，不得只在编辑表单里标一次。
- 本地验证允许走通四阶段**试算流程**，但不意味着 `released/effective`。正式预检/正式排产门禁继续拒绝本地草稿工艺、路线和未获客户批准的工站。不要为了能点击后续页面，把草稿状态暗改成 released，或放松现有正式校验。
- 本包只用已有产品。全新产品创建、正式主数据审批/导入、完整 BOM 编辑、客户批准工作流、自动 APS、周报告 B/C 段、临时 R&R 样本移除都不在本包。

## 实施任务

1. **工艺清单**：本地新增 `processId`、名称、工艺类型、说明、版本。必填校验、全局 ID 唯一、来源 `local-validation`、状态 `draft`；已有工艺可被本地验证路线引用，不强迫重新创建。页面列明“工艺”与“路线工序”的区别。重复或无效 ID 不得写入。
2. **路线副本与工序**：从已有测试产品的路线创建独立本地副本，不改原对象。选择工艺加入副本，显式输入或生成唯一 `operationId`，设置顺序和名称。插入/调整顺序后重算相邻工序的 predecessor/successor 引用；源路线顺序和引用不变。工序序号/ID 冲突、缺失工艺引用需显示具体错误。`Operation` 当前含兼容字段，新增草稿不能用隐藏的 24s CT、100% P/Q 或虚构工站冒充已确认参数；必要时调整类型/计算门禁，使缺值明确处于待补状态。
3. **工站与前置引用**：新工序可选择现有工站或本地模拟待投资工站，并维护主/并行/备用角色、客户批准标记、备用启用条件及 operation-station CT/每循环件数/P/Q。工站组关系按现有领域规则校验；不能默认把备用或待投资工站算作可排产。阶段物料/WIP 引用若缺失或不匹配，要具体指出，不生成假的已发布 BOM。允许继续记录 SA/R&R 草稿，但正式能力/路线结果保持阻断，直到所需引用和参数满足本地试算条件。
4. **验证与正式门禁分离**：增加显式的本地流程可用性判断，不复用或覆盖 `formalReady`。第一阶段能选中本地路线，第二、三阶段作用域跟随其 `productId/routeId/operationId/stationId`；第四阶段预检区分别展示“本地试算可继续”和“正式发布尚缺什么”。R&R、标准 SA、参数版本、周账/报告缓存必须按路线隔离；切回原路线，原数据及计算结果不变。若现有存储键缺 routeId，先补隔离和旧数据兼容，不得串到新路线。
5. **保存与清除**：本地验证工艺、路线、分配和草稿应自动保存到本机并可刷新恢复，数据文件/存储键带 schema version。提供仅清除本地验证数据的明确操作及确认；不要借用会重置所有样例和现有 R&R 的全局“重置样例”作为唯一清除路径。清除本地路线后，安全切回原路线，样例及上游对象字节级不变。页面持续标注本机验证数据不是正式主数据。

## 自动验收

- 新增工艺、复用已有工艺、新增路线工序分别测试；重复 processId/operationId、缺必填、错误工艺引用被拒绝。源路线、源工艺及其他产品不变。
- 在已有路线中间插入新工序并排序，序号唯一、前后序双向一致；删/改本地验证工序不得留下悬挂工站分配和 Stage BOM/WIP 引用，或应明确阻断删除。缺 CT、每循环件数、工站及 WIP 时不采用隐藏默认值。
- 本地草稿能被第一至第三阶段选中、保存标准 SA 与 R&R 并刷新恢复；正式 `validateProductRoutingMasterData` / preflight 仍拒绝草稿路线和草稿工艺。已发布原路线继续通过原有正式检查。
- 主/并行/备用、待投资和客户批准门禁与现有逻辑一致；不同路线同名工站、事件、参数版本、周账与 R&R 不串数据。清除本地验证数据不影响样例和已有原路线草稿。
- 页面交互回归真实完成“新建工艺 → 加入验证路线 → 分配工站 → 录入参数 → 标准 SA → R&R → 预检”，不能只断言 HTML 字符串。中英文、窄屏可读，不让编辑控件挤乱四阶段导航。运行 `npm run check`、`npm test`、`npm run build`；视觉检查遵循 `safe-html-preview`，不从终端启动系统 Chrome。交付时列明未覆盖的浏览器/人工风险。
