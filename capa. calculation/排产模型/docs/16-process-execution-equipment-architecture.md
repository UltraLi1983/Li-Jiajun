# 工艺、执行单元与物理设备：架构决策

状态：业务口径已确认；本文件是后续实现依据，不表示设备换绑功能已经交付。

## 身份与边界

| 对象 | 稳定身份 | 含义与归属 |
| --- | --- | --- |
| 工艺类型 | `processTypeId`（待实现） | 受控分类，如清洗、机加工；本地可扩展，将来可映射前置系统分类。 |
| 工艺定义 | `processId` | 可复用的“做什么”，如某道具体清洗工艺；独立于产品路线和物理设备。 |
| 路线工序 | `operationId`，并引用 `processId` | 某产品的某个路线版本在某个顺序使用该工艺；物料用量和前后序属于这里。 |
| 工序设备关联 | `operationEquipmentAssignmentId`（待实现） | 将某路线版本的工序与一台物理设备连接；`OP10-1`、`OP10-2` 是该产品工序的设备关联流水号，不是设备主键。 |
| 物理设备 | `equipmentId`（待实现） | 独立、唯一、长期稳定的实体设备身份，如“机加工1号”；不以工艺编号或尾缀充当设备 ID。 |

`OP10` / `OP20` 是产品路线内稳定的工序号；`OP10-1` 表示该路线版本的 OP10 所关联的第一台设备，不代表全局物理设备身份。同一设备可在不同工序出现，但两个关联共同占用该设备唯一的时间预算。换机要新建有时效的关联，旧关联及其流水号留在历史中；新设备分配新的关联号，不把旧号改指另一台设备。路线引用工艺定义，再给该路线工序配置可用设备；不要把一条工艺只能用于一条路线或一台设备写死。

## 工艺库：当前本地建档，未来上游接入

工艺库是排产四阶段之前的独立基础资料入口，不作为每次排产必须走过的一阶段。受控工艺类型保持在“机加工”“装配”等大类颗粒度；粗车、精车等差异写在具体工艺定义中，不强制增设类型层级。新增工艺先搜索并选择已有类型；确无合适类型时才进入新增类型，经重复项检查及二次确认后收录。系统保有包含标准中英文名称的受控类型目录，便于统一展示和以后映射上游系统。新增具体工艺至少要求手工输入名称和选择类型；系统分配稳定的内部 `processId`、初始版本、来源、创建时间和状态。可选企业业务编号与说明。相似名称提示复核，不仅凭名称合并或强行阻止。建立工艺不会自动修改任何产品路线，也不录入工站 CT、每循环件数或 P/Q。

现有本地验证表单让用户输入 `processId`、类型和版本，且放在第一阶段；这是任务包 15 的试验入口，不是最终工艺库交互。迁移时保留已有 `processId`，不要因改成系统生成编号而重写被引用的 ID。正式数据与本地验证草稿的门禁维持现状，不因工艺库独立而自动发布。

未来对接 ERP、项目管理或其他前置系统时，保存 `sourceSystem`、`externalProcessId`、来源版本及同步/生效信息，使用显式映射把外部身份关联到稳定的内部 `processId`。匹配冲突、同名异物或已被路线引用的字段变化需人工确认并形成新版本；导入不得静默覆盖本地记录或历史路线。外部工艺类型也按独立映射处理。

## 设备准入与工序关联

工站/物理设备是路线排产之前的资源主数据，不在产品路线编排或其他排产阶段从系统外新建。工艺库设独立的“工站与设备资源”区域：前置系统可用时按来源系统、外部 ID、版本及生效状态导入；前置系统缺位时在同一区域本地补录。本地申报现有设备记录申报设备编号、工站排产键、名称、可承接工艺类型、资料来源及本地复核状态；申报编号不是不可变物理 UID，复核也仅赋予模拟计算资格，不等于现场或上游主数据核验。待投资对象仅有规划资源号与规划依据，不冒领物理设备编号，也不计入可排产能力。未来实物到货且身份核验后才建立权威 `equipmentUid`，显式关联原规划资源和历史记录，不回写历史为“当时已核验”。设备类型能力声明不等于具体工艺资格；路线编辑只能选择已入库且兼容的资源，不能从排产界面新建。前置系统导入、权威 UID、资格审批和时效绑定仍待开发。

当前新资源不再要求先建立独立工站组：工艺类型定义候选范围，设备可声明一个或多个可承接类型，具体工站角色、备用门禁和计划份额在产品路线中确认。旧样例 `process-machining` ↔ `grp-machining`、`process-assembly` ↔ `grp-assembly` 及已存本地组关系仍按原规则读取，不重写历史 ID；组不再是新建工艺、登记设备或插入路线的必经层级。未来 APS 可利用同类型资源池动态排程，但本系统当前的静态份额和单设备唯一工时预算约束仍保留。

设备库先登记申报 `equipmentId` 和可承接的工艺类型，这只是本地候选声明；正式的设备身份和针对具体工艺的资格确认仍待接入。资格可记录状态、来源、有效期及审批/客户放行条件。工序设备关联至少包含路线版本、`operationId`、关联流水号、`equipmentId`、生效起止时间、长期/临时类型、来源或操作者及记录时间。更换新建设备关联，不改写旧关联。临时替机结束后的恢复也须有明确记录，不靠覆盖字段推断历史。

例如 `OP10-1` 关联“机加工1号”，换为“机加工2号”时截止旧关联，并取该路线工序下一个未使用流水号建立新关联（若 `OP10-2` 已被并行设备占用，则用 `OP10-3`）；流水号不改变设备的全局 ID。若同一物理设备同时承接 OP10 与 OP20，允许建立两项关联，但不可给两道工序各算一份完整可用工时。当前先采用全线统一的开班/停班日历；这只确定共同时间边界，不表示设备可以并行执行两道工序，也不抹平各设备实际故障与损失。未提供可核验的设备工时分配时，跨工序共用设备的计划件数须标记不可计算/待分配，不能静默双计或假设各占 50%。后续 APS 可接入按班次/时间段的分时分配接口，且每台设备各工序占用分钟之和不得超过该时段唯一的可用分钟预算。

相邻工序默认仍按工站池可互通计算；若产品路线存在固定流向（如 OP20 机加工01→OP30 装配01、机加工02→装配02），在该路线版本中记录 `stationFlowPolicies`，以稳定的工序 ID 与工站排产键保存允许配对。未连线组合不得参与路线计划/同窗件数；计算先按各工序用量换算成成品等效件，再按工站容量与允许路径求最大流。工序行仍可展示独立能力上限，但不能充当流转后的路线能力。旧路线没有策略时保持原有全互通口径；重排导致策略不再连接相邻工序时停止给出路线件数，需人工移除或重建连线。该周总量约束不是 APS 的时段级 WIP 排程，也不证明实际物料已按该路径流转；完整同周 Actual 仍需逐工站及流向记录。

CT、每循环件数、P/Q 按产品、路线工序和物理设备分别设置及版本化。换机可从旧设备复制为待确认草稿，但须人工复核并确认；未经确认不能当作新设备已发布参数。历史 R&R、已发布参数版本及计算结果保留当时的设备和参数版本引用。计划用机与实跑实际用机分开记录，不能把事后实际换机反写为历史计划。

## 与现有模型的衔接

现有 `ProcessMaster` / `Operation` 分别承载工艺定义 / 路线工序；`StationMaster.stationId`、`OperationStationAssignment` 和 `OperationStationParameter` 已支撑按工站分配与计算。`StationMaster.equipmentId` 是本地申报编号的兼容字段，不是权威 `equipmentUid`，也没有独立设备主档或有时效的设备—工站关联。现阶段 `stationId` 只是兼容性排产键，既不可按名称推断为物理设备号，也不可直接重命名为关联流水号。迁移时逐项建立旧 `stationId`、申报编号与真实设备 UID 的显式映射，并另存路线工序内的关联号；旧样例、计划、R&R、参数版本和报表历史引用保持不变。现有 `plannedShare` 是同工序并行设备的份额，不能充当一台设备跨 OP10/OP20 的工时分配比例。

## 实施顺序与验收边界

1. 工艺库独立入口、类型受控选择、内部/外部身份与本地来源记录；沿用任务包 15 已建的验证路线，不重做其草稿门禁。
2. 增加物理设备主档、工艺类型能力声明和具体工艺资格确认；把旧 `stationId` 显式映射到设备，保留旧 ID 和计算结果。
3. 增加路线工序内设备关联流水号、带时间的长期/临时关联及共享设备冲突检查；参数复制须经人工确认。计划、R&R 和产能计算读取指定时间的设备关系；跨工序共用设备在未分配工时时阻止重复计数，并预留后续 APS 分时输入契约。
4. 最后接入前置系统映射与同步。外部系统不存在时，本地入口仍可完整运行；接入后不静默替换本地已引用的定义。

深度代码实现分包交给 Cursor。每包须覆盖 ID 稳定、来源映射、时间边界、单设备不重复计产能、换机参数复核、历史不改写和旧样例回归；未做完第 3 步前，界面不得宣称支持按设备换绑计算。此处仅确认架构和未来接口，不表示设备库、资格、共享预算校验或 APS 排程已实现。
