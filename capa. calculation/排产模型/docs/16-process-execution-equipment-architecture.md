# 工艺、执行单元与物理设备：架构决策

状态：业务口径已确认；本文件是后续实现依据，不表示设备换绑功能已经交付。

## 身份与边界

| 对象 | 稳定身份 | 含义与归属 |
| --- | --- | --- |
| 工艺类型 | `processTypeId`（待实现） | 受控分类，如清洗、机加工；本地可扩展，将来可映射前置系统分类。 |
| 工艺定义 | `processId` | 可复用的“做什么”，如某道具体清洗工艺；独立于产品路线和物理设备。 |
| 路线工序 | `operationId`，并引用 `processId` | 某产品的某个路线版本在某个顺序使用该工艺；物料用量和前后序属于这里。 |
| 工艺执行单元 | `executionUnitId`（待实现） | 工艺下可独立排产的一路逻辑能力，如 `OP10-1`、`OP10-2`；编号可显示为工艺编号加尾缀，但内部身份不得依赖解析字符串。 |
| 物理设备 | `equipmentId`（待实现） | 独立、唯一、长期稳定的实体设备身份，如“机加工1号”；不以工艺编号或尾缀充当设备 ID。 |

`processId` 与 `executionUnitId` 属于同一逻辑工艺体系，后者必须明确引用前者；日常排产与 SA/R&R 主要聚焦执行单元。`equipmentId` 属于并行的物理设备体系，通过有时间边界的关系接入执行单元。路线引用工艺定义，再给该路线工序配置可用执行单元；不要把一条工艺只能用于一条路线或一台设备写死。

## 工艺库：当前本地建档，未来上游接入

工艺库是排产四阶段之前的独立基础资料入口，不作为每次排产必须走过的一阶段。新增工艺最少要求名称和受控工艺类型；系统分配稳定的内部 `processId`、初始版本、来源、创建时间和状态。可选企业业务编号与说明，用于区分同类型的具体工艺。相似名称提示复核，不仅凭名称合并或强行阻止。建立工艺不会自动修改任何产品路线，也不录入工站 CT、每循环件数或 P/Q。

现有本地验证表单让用户输入 `processId`、类型和版本，且放在第一阶段；这是任务包 15 的试验入口，不是最终工艺库交互。迁移时保留已有 `processId`，不要因改成系统生成编号而重写被引用的 ID。正式数据与本地验证草稿的门禁维持现状，不因工艺库独立而自动发布。

未来对接 ERP、项目管理或其他前置系统时，保存 `sourceSystem`、`externalProcessId`、来源版本及同步/生效信息，使用显式映射把外部身份关联到稳定的内部 `processId`。匹配冲突、同名异物或已被路线引用的字段变化需人工确认并形成新版本；导入不得静默覆盖本地记录或历史路线。外部工艺类型也按独立映射处理。

## 执行单元与设备绑定

工站组当前用于表达“该工艺可由哪些逻辑工站承接”，不是设备身份，也不要求一个组只能服务一个工艺。样例 `process-machining` ↔ `grp-machining`、`process-assembly` ↔ `grp-assembly` 已显式绑定且已发布样例只读。本地新工艺可先建为未绑定草稿，但加入验证路线前须至少绑定一个已有工站组；新建工站组时须同时选择一条本地工艺并建立绑定。修改绑定不得留下已分配工站不兼容，也不得把已入路线的工艺清成无绑定。绑定保存在本机验证资料中，未来对接前置系统时应按稳定 ID 做显式映射，不凭名称推断。

执行单元拥有稳定 ID、所属 `processId` 和业务展示号。物理设备拥有独立 ID。绑定记录至少包含 `executionUnitId`、`equipmentId`、生效起止时间、类型（长期换机/临时替机）、来源或操作者以及记录时间；更换创建新的绑定记录，不改写旧记录。临时替机到期后按明确的原绑定恢复规则处理，不能靠覆盖字段推断历史。

例如 `OP10-1` 原绑定“机加工1号”，指定时间改绑“机加工2号”：`OP10-1` 不变，旧绑定截止，新绑定生效。`OP10-2` 若也使用“机加工2号”，两条绑定可以描述候选关系，但同一时间的实际排产/产出不能把这一台设备计成两份并行能力；冲突应在排程或计算前显式提示。设备可承接不同工艺，设备身份不随工艺切换。

换机时应提示按新设备复核该工序执行单元的 CT、每循环件数、P/Q；未经复核的旧参数不得静默视作新设备的已确认参数。历史 R&R、已发布参数版本及计算结果保留当时的设备和参数版本引用。计划绑定与实跑实际用机分开记录，不能把事后实际换机反写为历史计划。

## 与现有模型的衔接

现有 `ProcessMaster` / `Operation` 分别承载工艺定义 / 路线工序；`StationMaster.stationId`、`OperationStationAssignment` 和 `OperationStationParameter` 已支撑按工站分配与计算，但没有独立 `equipmentId` 与有时效的设备绑定。现阶段将 `stationId` 视为兼容性的逻辑排产键；不要根据名称（如“机加工01”）自动推断它就是物理设备 ID，也不要直接重命名现存键。样例数据需要逐项确认 `stationId` 对应的执行单元与真实设备，再建立显式映射。迁移须保留现有计划、R&R、参数版本和报表的历史引用，并验证旧样例计算不变。

## 实施顺序与验收边界

1. 工艺库独立入口、类型受控选择、内部/外部身份与本地来源记录；沿用任务包 15 已建的验证路线，不重做其草稿门禁。
2. 增加稳定执行单元身份及 `processId` 父子关系；把现有 `stationId` 逐步映射为逻辑执行单元，既有 ID 和计算结果保持兼容。
3. 增加物理设备主档、带时间的长期/临时绑定及冲突检查；再让计划、R&R、参数复核和产能计算读取指定时间的设备关系。
4. 最后接入前置系统映射与同步。外部系统不存在时，本地入口仍可完整运行；接入后不静默替换本地已引用的定义。
