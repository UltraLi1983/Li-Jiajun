## Phase 1：计算核心固化

目标：把当前 HTML 里的计算逻辑迁移到 `src/engine`，并先固化业务计算口径。计算核心不是从公式开始，而是先确认参与计算的元素、结果输出、适用范围和不参与计算的边界。

### 业务确认清单

1. 计算范围

- 计算对象层级：产品 / 工序 / 工站 / 产线 / 项目。订单或工单只作为需求与记录引用，不作为 dashboard 一级选择对象。
- 时间范围：24H / 48H detailed R&R、自然周、自然月、指定排产窗口。
- 时间颗粒度：分钟级事件账、小时级汇总、班次级汇总、日/周/月级模拟。
- 工厂日历：6 天制、7 天制、自定义停工日、跨天班次。

2. 参与计算的时间元素

- production。
- setup / changeover：序列相关，不作为固定平均损失。
- break。
- maintenance。
- planned stop。
- unscheduled / not planned：未排产、不开机、不来人、不消耗，不进入可用产能。
- abnormal interruption：量产实绩或 R&R 观察到的非计划中断，需保留来源结构。

3. 参与计算的产出与节拍元素

- standard CT。
- pieces / cycle。
- start time / end time，由系统计算 elapsed minutes。
- OK qty / NOK qty，由系统计算 actual qty 与 quality rate。
- observed CT，由 elapsed minutes / actual qty 计算。
- expected qty 与 hidden loss，用于定位未被事件账捕捉的损失。

4. 计算结果

- Best case：纯排版分钟加上已发布的 CT 和每循环件数，不乘 P、Q，不含非计划中断。
- Most likely：同一套计划分钟再按班次扣已接受的非计划停机，件数乘已发布的 P、Q。周账和月账预览已按此计算。它不是现场根因调查的前置条件，也还不是正式跨工站产能。
- Actual SA：基于实绩事件账回算，不作为排产输入。
- Performance rate：由 standard CT 与 observed / planned CT 关系得出。
- Quality rate：由 OK / NOK 得出。
- Capacity result：按 SA、Performance、Quality 分拆后再合成，不只保存 OEE。
- Bottleneck / gap / utilization / risk flags。

5. 不应混入计算的内容

- 不把未排产时间当作 open capacity。
- 不把 R&R 中偶发 abnormal 直接覆盖长期 planned baseline。
- 不只存一个 OEE 百分比。
- 不把 setup 简化为固定平均损失。

## Phase 2：标准 SA 设定与时间窗口投影

目标：在产品工艺路线与工站分配之后，建立可核对的工站标准状态账。生产日从可配置的白班开班时刻起算 24 小时，支持 1–2 个生产日及 8H/12H 完整班次；按事件账记录换型、休息、维护等。With breaks 用完整生产日作分母（含非排班），Without breaks 用排班分钟减计划休息作分母；后者是班内开动/OEE 参考。R&R 短时观察不受完整班次约束。之后按明确的重复规则或计划投影至更长周期，也可将窗口仅作为参考或极限场景。

交付：

- Product definition：周需求、版本、项目、需求场景（当前正式版已支持 mock edit）
- Routing definition：正式模式从已发布 ProcessMaster 中选择工艺过程，维护 operation sequence、工艺含义、Route version / effective period；当前 UI 只支持展示和已有工序的验证模式 mock edit，尚不能新增工艺或工序
- Stage BOM / WIP context：为每个 operation 记录阶段输入、消耗、输出和 WIP 状态引用；第一版只做追溯，不展开完整 BOM 计算
- 工序件数换算（本地首段已接入，5.21 已于 2026-10-19 通过）：每个产品路线工序记录“每件目标成品需要的本工序目标产出/WIP 件数”，离散件数用 1、2 等正整数，不再沿用原表 `Capacity Calculation` 第 22 行的百分比来兼指用量与工序覆盖比例。正式来源优先为上游阶段 BOM/工艺主数据，并保留来源、版本、生效期；前置系统尚未提供时，第一阶段验证模式可本地维护。产品需求已是独立零件号的纯件数，本模块不再做整车需求的 EBR/VR 换算。
- 正式版默认只选择上游主数据路线；本地新增工艺和工序仅作为后续验证模式能力，不进入正式主数据
- Capability group：定义可承接同一 operation 的工站组
- Station assignment rule：series / primary / backup、parallel、backup 前置条件、客户认可 gate（当前正式版已形成专项页）
- Operation-station parameter：CT、pieces/cycle、P rate / Q rate 新建时默认 100%。第一阶段已支持在本地验证编辑态，为已有工序—工站确认 CT、每循环件数及 P/Q，生成标明 `manual` 来源的本机参数版本并立即参与计划计算；刷新后从浏览器恢复，重置样例时清除。已有 R&R 记录或发布版本时仍可新建下一版预设，提交前需确认新版 CT/P/Q，并复核新 CT 下的 P；旧版本和现场记录不被改写，当前对比与建议会按新基线重算。它不写入上游主数据，也不替代正式的参数创建、审批和持久化流程；新增工序/工站参数的完整前置配置仍按下述验证模式任务推进。
- `piecesPerCycle` 是机台单循环产出（cavities），按工序—工站分别维护；上面的工序件数换算是每件成品所需该工序产出，按产品—路线—工序维护。二者不能互相推断，也不能与工站占用份额或 P/Q 混用。
- Capacity share profile：项目阶段 allowed share，量产阶段由 forecast 计算 required share
- Batch HU policy：基于最小工序完成品 HU 的整倍数
- 6 天/7 天/自定义工厂日历切换
- 日历事件批量复制
- 按排产顺序自动生成 setup 事件
- 按工站及产品切换方向维护换型矩阵；验收 A → B 为 60 分钟、B → C 为 120 分钟时两次换型累计 180 分钟，反向组合独立维护，缺失组合不默认零，手工与自动事件不得重复计入。
- 复制模式仅平移源窗口已有事件，包括源内换型，不追问窗口前产品，也不自动生成跨窗口换型。另编整周模式若显式安排多产品顺序，才按切换方向计算换型；具体口径见领域模型 SetupMatrix。
- 按班次模板生成 break / maintenance
- Best case / Actual SA 分层显示；Most likely 与 Best case 同为排产口径，按班次扣非计划停机，计算尚未实现
- 计划时间轴编辑器：使用具体 Start time / End time 和跨日边界，系统自动计算 duration
- 同一工站事件防重叠校验，隐式 gap 提示使用者显式补为 unscheduled / not planned
- 时间轴支持全屏查看；Planned SA 时间轴只承载计划状态账，不承载产出明细录入

第一阶段可视化路线编排已接入本地验证路线草稿：流程节点不显示起止占位，已发布路线只读；节点内选工站仅展开该工站参数，插入与重排更新真实工序顺序和前后序。5.18 已于 2026-10-19 通过。此项不等于工序设备关联/物理设备绑定已实现。

目的：在上游产品工程 / 工艺主数据尚未接入时，先允许用已有测试产品的独立本地验证路线验证“工艺选择 → 工站分配 → 标准 SA → R&R → 产能预检”的完整流程；全新产品创建另包处理。这里有两个不同动作：新增可复用的工艺条目（ProcessMaster），以及从工艺清单选择条目并加入产品的本地验证路线（Operation）。不能只修改已有 Operation 的名称来冒充新增工艺。实施边界见 `docs/15-cursor-local-process-route.md`。

实施任务：

1. 在明确标识的本地验证模式中维护工艺清单：新增 `processId`、名称、工艺类型、说明和版本；校验 ID 唯一、必填字段及来源，标记为 `local-validation`。已存在工艺可直接选择，不要求重复创建。
2. 从清单选择工艺，向不改写已发布样例的本地验证路线副本新增 Operation，生成独立的 `operationId`，维护工序顺序和工艺含义，并绑定 `processId`；排序或插入后更新前后序关系。工序是产品路线实例，不能与可复用工艺主数据混为一条记录。
3. 为新增工序继续选择现有或模拟新投资工站，维护主/并行/备用角色、备用启用条件、客户批准门禁和 operation-station 参数。缺少工站、关键参数或必需的阶段物料/WIP 引用时，预检给出可理解的阻止项。
4. 验证模式数据只存在本地测试场景，支持重置，不覆盖样例或上游主数据；页面持续标明其测试来源。需明确测试条目的“可用于本地流程验证”与正式 `released/effective` 门禁的区别，不得因本地验证而放行正式排产或把草稿静默当作已发布主数据。

验收：选择已有测试产品，在其验证路线新增一条工艺并加入工序后，能完成工站分配并走到该工站的标准 SA、R&R 和产能预检；重复 ID、缺少关联或未满足正式发布条件时有明确提示；重置后测试数据消失，已有正式/样例数据不被改写。自动测试覆盖新增、插入顺序、引用一致性和正式门禁；人工烟测覆盖上述端到端路径。全新产品的创建另作产品主数据任务，不偷渡进本任务。

排期：这是 Phase 2 前置配置的补充任务，不表示当前已完成，也不阻塞已有 Product A 的 R3-2 至 R3-5 开发；在用“全新产品”做正式版端到端验收前必须完成。

### 工序产出件数与成品换算（本地首段已接入，5.21 已于 2026-10-19 通过）

1. 在第一阶段的产品路线工序配置中显示本工序目标产出/WIP 及“每件成品所需本工序产出件数”。上游已发布且有效的阶段 BOM/工艺主数据存在时读取并标识来源、版本和生效期；仅在缺少上游用量时允许本地验证输入，不静默覆盖上游数据。已知样例的 1:1 也须作为显式数据，不以字段缺失代替。
2. 将已校验用量送入同窗路线产能引擎：各工站先按自身 CT、`piecesPerCycle`、P/Q 和本窗口 100% 生产时间计算，随后同工序工站相加，再除以本工序每成品所需件数，最后取串行工序瓶颈。70% / 30% 一类占用不在本窗口扣减。Actual 用同窗各工站 OK 件数作同一换算；需求按成品件数输入并乘用量得到各工序需求。缺失、非正整数、单位不符或来源版本失效时，明确阻止路线级成品等效计算，但保留工站原单位结果。
3. 用上述前置数据替换第四阶段临时的“确认各工序件数均可按 1:1 换算”复选框；第四阶段只展示所用用量及其来源，不再让用户临时定义换算。工序分流/覆盖比例与多输出 BOM 逐物料用量另设边界，不复用这个整数或 70%/30% 工站占用份额。

已交付本地首段：第一阶段可查看工序用量与来源；本地路线无阶段 BOM 时可直接录入并确认正整数用量，刷新后恢复本机输入，但不生成正式 BOM。新建本地副本不继承源路线的旧 1:1 用量；既有草稿中未带本地确认版本的旧值也不视为已确认。第四阶段展示用量来源，直接做同窗路线换算，不再要求临时 1:1 勾选。阶段 BOM 有有效且匹配的用量时优先读取；缺失或无效用量阻止路线级计算。路线 Actual 等效件数向下取整。

验收：分别验证 1 件与 2 件 WIP/成品、不同工站 cavities、已有本地 Stage BOM 用量优先、本地输入回退、缺失用量门禁及来源版本/生效期变化；核对计划/Actual 瓶颈和需求余量，并确认 SA 时间轴及已保存 R&R 原始记录不随换算改动。正式上游导入接口、审批与持久化未交付，不能把本地验证输入视作正式主数据。

### 标准窗口投影的实施任务

1. **冻结源窗口（本地基础能力已接入）**：在标准 SA 页面选定一个工站的 24H/48H 事件账，校验起止时钟、事件类型、无重叠及完整覆盖；空档须显式标为未排产。冻结时记录来源版本和事件快照；继续编辑源事件后标记旧快照过期。当前冻结仅在浏览器会话内有效，不代表正式批准。
2. **选择用途与整周编排方式（平稳日已接入，2026-10-11 人工烟测通过）**：长周期展开按需使用，不妨碍只保留短窗口作参考。源窗口保留真实时钟，供跑线对照，并作为周内的极端或复杂日。其余工作日只编一个平稳日，同周其他未复制源窗口的工作日套用它；非工作日不套用。平稳日只记动作分钟，不伪造起止时钟。复制日保留具体事件。两者汇入同一日账。不能将 SA 百分比直接乘以周/月分钟数。
3. **整月重复（已接入，2026-10-11 人工烟测通过）**：一周成立后，整月按四周重复这一周的结构。每周都会发生的换型留在复制源日或平稳日里。一个月一次、两次或三次的换型只在月账记单次分钟和次数，从整月生产时间扣除，不改各周；同一次换型只进一处。Most likely 的班次预留已在周账和月账下预览。
4. **保存来源与计算结果（四周会话预览已接入；正式保存待开发）**：每条复制事件保留源事件和源版本。源窗口改变或班制改变后，依赖源的结果失效；平稳日分钟保留并按新的开班锚点复核。结果尚未持久化，也未进入正式跨工站产能。排产将同时使用 Best case 与 Most likely，二者共用这份纯排版时间账和已发布的 CT/P/Q；Most likely 另按班次扣非计划停机。Actual 只评价已发生窗口。

周级口径已确认：工作日须由计划预先指定，零产出日仍算工作日；With breaks = 工作日生产分钟之和 /（工作日数 × 1,440），Without breaks = 工作日生产分钟之和 /（工作日排班分钟之和－计划休息分钟之和）。另列整周日历利用率 = 周生产分钟 /（7 × 1,440），用于展示增开工作日/班次的机会，不标为 SA。原表只按每周班数对应 5/6 个满 24H 工作日，8H×2 班及班内未排产属于本系统扩展。2026-10-10 起，页面按「复制源日 + 一个平稳日套用到其余工作日 + 整月重复该周」生成本地预览。月内一次到三次的换型只从整月生产分钟扣除。Most likely 班次预留已在周账和月账下预览。方案 2 的整周逐日详细事件仍待开发。

验收按 2026-10-10 口径：未复制源窗口的工作日共用一个平稳日；整月重复该周；每周换型留在日账，月内一次到三次的换型只进月账且不改各周。Best case 时间账已能这样预览，5.12 已于 2026-10-11 通过。`docs/12-cursor-week-month-capacity.md` 已把当前工站周/月两档分钟换成良品件数，5.13 于 2026-10-11 经用户确认通过。不扩展为正式路线产能。P、Q 的进一步反写比例仍待职能确认。

## Phase 3：Run & Rate 参数校准闭环

### 当前实施顺序（2026-09-25 确认）

1. **R1 实际事件账与双轨时间轴**：R&R 按选定产品 / 工序 / 工站新建独立实际时间段，不复制或改写标准 SA。实际段使用明确日期和时钟，默认下一段起点等于上一段终点；允许编辑、删除并校验重叠、空档与观察窗口。生产段录入 OK / NOK、每循环件数及证据，休息、换型、维护和异常段录入真实原因。计划与实际轨道使用同一时间刻度，显示时间开动率差异；未覆盖的时间标为待补录，不当作生产或停机。
2. **R2 速度损失归因**：未完成节拍校验时，用同产品、工序、工站、每循环件数下最快且有效的生产段平均节拍作为观察参考；显式停机只计一次，其余慢速段的产出缺口计入推断时间开动率损失。完成节拍校验后使用经确认的标准节拍。可接受的慢速偏差可不设置；不设置时全部超额时间计入推断时间损失（方式 B）；设置时只能为 0–5%，容差内计入性能率／速度达成率损失、容差外计入推断时间损失（方式 A）。快于经确认标准节拍时停止自动归因，提示复核数量、节拍及每循环件数。
3. **R3 证据与校准**：逐段对比计划与实际时间，保留显式/推断标记，形成标准 SA、CT、P、Q 的可选建议，不自动覆盖标准基准。未知 root cause 不阻止 Best/Actual SA；只有时间空档、重叠或关键数量/节拍错误影响结果完整性。

历史阶段记录：路线主数据校验引擎已接入路线配置和产能预检；R1 已接入独立实际事件账、编辑/删除、同轴计划/实际轨道和覆盖检查；R2 已实现并接入节拍归因核心及容差输入；R3-1 逐段计划/实际对账和 R3-2 异常证据结构已通过人工烟测；R3-3 已接入参数建议草稿、本地确认、生效日期及独立的 CT/P/Q 本地发布动作，待浏览器人工烟测。第四阶段已厘清 R&R 建议边界：休息超时、维保、计划停机等动作差异只进入 Actual SA 和待纠偏，不作为标准时间参数发布；换型总分钟只作诊断，后续标准规则必须按单次切换方向定义。单工站 Best/Actual 预览及 R3-4 的同窗跨工站本地试算已接入；标准窗口整周复制、逐日另编和四周独立编排的会话预览已接入，但这是过渡交互。目标改为复制源日、一个平稳日套用到其余工作日，再整月重复该周；正式跨周期产能、Most likely 班次预留、R3-5 和投影持久化仍未交付。此段曾要求“本窗口需求”并把草稿视为会话内存；这不是当前需求入口和持久化现状的权威说明。后续需求以逐日客户需求账为源，正式持久化、版本与发布边界以新契约和实际实现为准。

本轮暂不建模人工疲劳随班次变化的节拍曲线；APS、自动采集和复杂审批流仍属后续阶段。

### 临时 R&R 验证样本（正式启用前必须移除）

- 已加入临时 24 小时 R&R 验证样本，供当前有生效 CT 与每循环件数的工站一键加载，包括本地压铸工站。样本按所选工站当前参数生成，计划、实跑和节拍样本按工站隔离；它不是真实现场证据。加载只替换当前工站的实跑记录，已有记录时先征求确认；标准 SA 计划不被改写，非排班时段会阻止加载。
- 第四阶段可基于完整记录显示单工站 Best case 与 Actual 草稿预览：Best case 用标准生产分钟、标准 CT 和 Planned Q 拆出理论总产出、理论 OK/NOK；Actual 用实际生产分钟、现场 OK/NOK 回算 Actual CT 与 Actual Q。差额按时间、性能率和 NOK 拆分。额外休息、显式异常和推断时间损失按 Actual SA 口径扣减生产可用时间，原因可待查且不在性能率或良率中重复扣减。该预览不包含需求份额和多工站分配，不等于 R3-4 的正式产能输出。
- **正式启用门禁**：R3-1 至 R3-5 与相关人工验收完成后，删除验证样本模块、加载按钮、样本专属状态与相关文案；将固定数字断言替换为通用计算测试，确认发布包中没有该验证样本入口或伪现场数据。移除前不得将此工具标记为正式生产可用。

## Phase 4：排产系统接口

目标：让该工具成为运营系统中的参数服务。

交付：

- 输入 API：需求预测 / 工单引用、产品路径、能力组、工站分配规则、工站日历、换型矩阵
- 输入 API：R&R observation、abnormal loss observation、历史实绩
- 输出 API：Best case 可用分钟、Most likely 可用分钟、Actual 回算结果
- 输出 API：瓶颈、风险、产能缺口、参数建议更新
- 支持导入历史排产和历史换型损失
- 支持 APS 请求指定排产窗口、时间颗粒度和 SA 视角
