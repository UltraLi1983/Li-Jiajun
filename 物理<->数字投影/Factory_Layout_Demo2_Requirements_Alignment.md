# Factory Layout Demo 2 — 需求与现有系统信息对齐（讨论稿）

> 版本：v0.1｜日期：2026-11-02｜状态：**待双方确认，不作为开发指令**  
> 目的：在启动后续编码、布局调整、Transportation 路线规划之前，统一事实、假设、原系统能力与待确认需求。

## 0. 使用原则与标记

- **[U] 用户已明确提出**：原则性要求，除非用户修改，否则视为约束。
- **Transportation**：地面行驶与空中吊运的统一任务链；工具可包括 AGV、Dolly / Tugger、叉车、地牛、行车等，具体准入、覆盖空间和路径责任按运输段配置。
- **[D] Demo 2.1 已有**：现有模拟文件中可直接检查到的数据或实现；不代表业务要求已验证。
- **[H] 暂定假设**：为了绘图临时设置，尚未得到业务确认。
- **[T] 待讨论**：需要进一步展开、定义或验证。
- **[R] 待从原系统核实**：目前没有原始 Demo2 主程序或完整仓库，不推断其真实功能。

**范围边界**：模拟参考浙江海威相关铝合金汽车零部件业务，但不是浙江海威真实厂区的测绘图、设备清单或产品工程图。任何公开产品型号、实际尺寸、工艺路线和设备配置均应另附来源并逐项核实。

## 1. 目标与交付形态

1. [U] 以二维工厂 Layout 为基础，形成机器可读取、人工可修改的结构化数据。
2. [U] 支持 CSV 手工修正，软件重新读取后自动绘制厂区、车间、物料流及 Transportation 路线。
3. [U] 在固定产线的约束下，所有物料流必须经过**物料主干道**，再由主干道接入工站。
   - [T] 吊运任务可能在行车覆盖区内由工位直达工位；“全部经过地面主干道”与吊运段的适用边界需单独确认。
4. [T] 区分“布局可视化”“物流网络可达性”“路径优化”“多车调度”四种能力，不默认一次性实现。
5. [T] 确认输出：CSV、内部 JSON、二维 PNG/SVG、可执行生成脚本、验证报告及版本记录。

## 2. 产业原型及产品族

- [U] 以浙江海威的产品工艺结构作为模拟背景。
- [H] 暂采用汽车铝合金壳体产品族，如 OBC 壳体、EPS 壳体等；产品名称及与具体工厂的对应关系仍须核实。
- [T] 建立产品族参数表：`product_family_id`、名称、产品包络尺寸（L/W/H）、单件质量、周转器具尺寸、每器具件数、物流单元质量、年/日需求量、批量与节拍。
- **重要**：之前讨论的产品尺寸只是模拟假设，不能标为海威实测数据。Transportation 通行空间设计优先采用**装载后周转器具/托盘的外廓尺寸**，而非仅采用零件本体尺寸。

## 3. 工艺与建筑边界

| 建筑 | 主工艺 | 必须考虑的区域 | 备注 |
|---|---|---|---|
| B01 铸造 | 铝料接收/检验→熔炼→压铸→后处理→输出 | 铝料 IQC、铸造生产、出料暂存、NG 隔离 | [U] 独立 Building；热环境 |
| B02 机加工 | 压铸 WIP 接收→机加工→检验/清洗→输出 | **压铸 WIP 存储**、固定机加工产线、NG 隔离 | [U] 不单独设置常规 IQC 区 |
| B03 装配 | 机加工品接收→装配→测试/包装→输出 | 装配线、出入料缓冲、NG 隔离 | [U] 不单独设置常规 IQC 区 |

- [U] 三个 Building 位于一个大厂区内，原则上单层，不涉及多层楼宇物流。
- [U] 铸造与机加工/装配分离；后两者需要考虑温度环境及尺寸稳定性。
- [U] 每个车间设置不合格品隔离区，短期周转，原则上每班或每天清理。
- [T] NG 区容量、清运频次、路径、返工/报废去向、隔离方式需要量化。
- [T] 热处理、切边、去毛刺、清洗、检验、包装等是否在三级工艺下进一步定义为工站/工序。
- [T] 机加工与装配是两个独立 Building 还是同一温控建筑内分区？当前 Demo 按独立 Building 建模。

## 4. 位置锁定与空间几何

- [U] **产线位置强制锁定**：算法不得自动平移、旋转或交换产线。
- [T] 锁定层级应区分：建筑外轮廓、生产线外廓、单机设备、工站物料 Port、主干道、缓冲区。当前 Demo 的 `locked=1` 覆盖了全部对象，无法表达哪些空间允许优化。
- [T] 明确坐标原点、X/Y 方向、长度单位、旋转定义、实体几何（矩形/多边形）、占地与安全包络。
- [T] 明确生产线输入/输出 Port、人员通道、检修空间、消防通道、建筑出入口和车辆禁行区。

## 5. 物流主干道与 Transportation 路网

- [U] 所有物料流先进入物料主干道，再由主干道进入工站；不得任意穿越生产区域抄近路。
- [T] 需确认这条规则是否同时约束：原材料入厂、工站间 WIP、NG 清运、空托盘回流、成品出货。
- [T] 需要将每栋建筑的室内主干道、支线、物料 Port、室外跨楼道路和门口转运点连接成**可验证的有向图**。
- [T] 每条 Edge 定义长度、净宽、单/双向、限速、可通行车辆、禁行条件；每个 Node 定义位置、类型、归属、转弯/等待能力。
- [T] 先按运输工具类型校验静态可达性与路径，再讨论多车交通冲突、会车、调度、补能与拥堵。
- [T] 室内外跨建筑运输的车辆能力、坡道/门槛、气候、车辆类型与交接方式待定。

### 5.1 行车吊运与三维空间（新增讨论）

- [U] 本轮只规划**生产物料流中的吊运**，包括大质量零件在工位、缓存位与地面运输 Port 之间的移动；换模、维修等非物料流吊装路线暂不纳入。
- [U] 铸造车间有行车；机加工车间和装配车间有小型行吊。三个车间均作为已有吊运资源区域，具体覆盖范围、能力及起落点仍需核实，不能仅凭“有行吊”判定任意两点可达。
- [T] B01/B02/B03 分别记录现场行吊参数；小型行吊的实际类型、安装方式、覆盖形状和工作高度以现场资料为准。
- [T] 把既有起吊工位、落位工位和真实缓存位定义为 `LiftPort(x,y,z)`。地面与吊运在同一物理 Port 衔接，不凭空增设“交接站”。

| 对象 | 首版需要记录的字段 | 规划作用 |
|---|---|---|
| 物料吊运任务 `lift_tasks.csv` | 来源/目标 Port、物料+器具+吊具总质量、吊载外廓、次数/班、吊点/姿态 | 判断物料流吊运的任务量 |
| 行吊资源 `crane_resources.csv` | Building、设备类型/安装方式、额定能力、XY 覆盖、有效钩高范围、各运动方向速度、可用时间 | 判断覆盖、能力及资源负荷 |
| 起落点 `lift_ports.csv` | 物理工位 ID、XYZ、允许的取放方式、装卸时间 | 接通地面段与吊运段 |
| 三维约束 `overhead_constraints.csv` | 梁、管线、设备上沿、禁吊区的 XY 轮廓及 Z 范围 | 校核吊载和吊具的通行包络 |
| 吊运路径 `lift_routes.csv` | 起点→起升→水平移动→下降→终点、负责行车、预期高度带 | 展示和计算一段真实吊运任务 |

**计算顺序**：先校验起点和终点是否在行车覆盖区、总吊重与吊具是否匹配、钩高与吊载外廓是否足够、路径是否进入禁吊/障碍空间；可行后再估算吊挂、起升、大车/小车移动、下降、落位与等待时间，汇总行车占用率和地面运输段负荷。任何必需的高度或障碍数据缺失时，结果标为“待人工复核”，不输出已验证的可行路线。

**展示与阶段**：Demo 先把行吊作为 Transportation 工具类型，在二维平面标注其覆盖 caution 区；物料流任务显示所用工具与起落点。caution 区只提醒人工核实覆盖和空间条件，不能单独作为吊运可行结论。侧视高度、三维碰撞与多台行吊调度留待后续阶段。

**待确认的主干道规则**：建议“地面运输段经物料主干道；吊运段按行车覆盖和三维禁行空间校核；跨楼运输在实际起落点/装卸 Port 衔接”。这是对现有规则的提案，待确认后再改为 [U]。

**依据**：中国现行《[起重机械安全技术规程（TSG 51—2023）](https://www.samr.gov.cn/tzsbj/zcfg/aqjsgf/aqjsgf/art/2025/art_ca8bed560bf34ad199c4d8abd8af4a24.html)》及其[第 1 号修改单](https://www.samr.gov.cn/tzsbj/zcfg/aqjsgf/aqjsgfxgd/art/2025/art_0b13c89a986c4f99a0f8df83d5d458f2.html)列有桥式起重机的额定起重量、跨度、起升高度、吊具及机构速度等参数；[GB/T 6067.5—2014](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=A34B63E93D3AC59897C5D031CE547EC5&refer=outter)针对桥式和门式起重机。这里引用它们确定需要采集的参数类别，不代替具体设备和现场工况核验。

### 已识别问题（后续需处理，不在本轮直接修改）

1. **对象碰撞/重叠**：例如 B01 熔炼/IQC 与示例固定产线、B02 WIP 与固定产线、B03 FG 与固定产线在空间上存在重叠可能；应以几何检测结果为准进行全面审查。
2. **锁定语义过宽**：全部对象锁定会使缓冲区和路网优化失去调整空间。
3. **路网字段不足**：当前 Edge 无长度/净宽/限速等参数，尚不具备可靠 Transportation 路线计算条件。
4. **流量粒度过粗**：当前仅建筑间 3 条物流流向，无法计算工站级运输资源需求。
5. **WIP 容量尚未建模**：已有区域坐标，但缺少托盘规格、库位数和停留时间。
6. **未区分真实资料与模拟假设的来源**：需为产品、尺寸、工艺和设备建立 `source/status` 字段。
